# REQ-2026-123 요구사항

추적 파일의 병합 충돌 마커 가드 — 실사고 재발 방지

## 배경

2026-08-10 통합에서 CHANGELOG의 병합 충돌 해소 스크립트가 CRLF 줄바꿈 때문에 조용히 실패해,
**충돌 마커(`<<<<<<<`/`=======`/`>>>>>>>`)가 남은 파일이 main에 push됐다**(병합 커밋 `65c067f` —
후속 `9512d43`으로 수동 정정). 당시 **전체 스위트가 그린**이었다 — 어떤 검사도 추적 파일의 마커를
보지 않는다. 같은 실수는 사람·에이전트 모두 반복 가능하며(충돌 해소는 통합마다 일어난다),
검출 비용은 테스트 하나다.

## 요구

- **R1** — git 추적 텍스트 파일 전체에서 **줄 시작의 충돌 마커**(`<<<<<<< ` 또는 `>>>>>>> `)를
  검출하는 가드 테스트를 추가한다. 발견 시 파일·행 번호를 나열하며 실패한다.
- **R2 · 오탐 경계** — 단독 `=======`는 검사하지 않는다(markdown setext 헤딩 밑줄과 충돌 —
  마커 세 종은 함께 나타나므로 두 종 검출로 충분하다). 이 가드 테스트 자신과 감사 아카이브
  (`workflow/REQ-*/responses/**` — 과거 리뷰 응답 본문에 마커 서술이 있을 수 있음)는 제외한다.
  바이너리·node_modules는 대상이 아니다(git 추적 텍스트만).
- **R3 · 변이 검사** — 마커를 가진 임시 파일이 검출되는 것을 테스트 자신이 증명한다
  (가드를 넣었으면 일부러 깨뜨려 실패를 확인한다는 저장소 규칙).

## 제약

- 게이트 배선 없음 — 전체 스위트(및 test:fast)의 일부로만 돈다(테스트 실행 계층 계약 유지).
- 검사 문자열을 소스에 리터럴로 두면 이 파일 자신이 걸린다 — 동적 구성으로 자기 제외를 대신한다.

## 완료 기준

1. 추적 파일에 마커 줄이 있으면 테스트가 파일:행과 함께 실패한다(변이로 확인).
2. 현재 트리에서 그린이다(기존 오탐 0).
3. 제외 규칙(responses 아카이브·자기 자신)이 문서화·테스트돼 있다.
