## 핵심 설계 결정

### DEC-1 · 검출 대상은 두 종의 줄-시작 마커, `=======` 단독은 제외

git 충돌 마커는 `<<<<<<< <label>`·`=======`·`>>>>>>> <label>` 세 줄 세트다. `=======`(7 equals
단독)은 markdown setext 헤딩 밑줄로 합법이라 오탐원이다 — 세트는 항상 함께 나타나므로
**`<<<<<<< `·`>>>>>>> `(7문자 + 공백) 줄-시작 검출**만으로 사고 클래스를 잡는다(R2).
패턴은 소스에 리터럴로 두지 않고 `'<'.repeat(7) + ' '` 식 동적 구성 — 이 테스트 파일 자신이
자기 패턴에 걸리는 순환을 구조적으로 없앤다.

### DEC-2 · 대상 = `git ls-files` − 제외 경로 − **내용 스니핑 바이너리**

- 제외 경로: `workflow/REQ-*/responses/**`(감사 아카이브 — 과거 응답 본문은 편집 금지 대상이고,
  리뷰 응답이 충돌 마커를 *서술*했을 수 있다).
- **바이너리 판정은 확장자 목록이 아니라 내용이다**(설계 r01 P1): git 자신의 휴리스틱을 따라
  **선두 8,000바이트에 NUL(0x00)이 있으면 바이너리**로 보고 건너뛴다. 새 바이너리 fixture가 어떤
  확장자로 추적되어도 오탐하지 않는다.
- 이 가드 자신은 동적 패턴이라 별도 제외 불요(DEC-1).
- 성능: 추적 파일 ~수백 개 — 파일당 선두 8KB 스니핑 + 텍스트만 전문 읽기. fast 계층에 포함된다.

### DEC-3 · 변이 검사는 **실제 수집·스캔 경로**를 hermetic repo로 통과시킨다

검사를 `collectAndScan(repoRoot) → {rel, line, kind}[]`로 구성한다 — `git ls-files -z` 수집 →
제외 필터 → 스니핑 → 마커 스캔까지 **한 함수**다. 순수 함수 주입 검증만으로는 수집·읽기 경로의
회귀(예: content가 빈 문자열로 매핑)가 잡히지 않는다(설계 r01 P1). 변이 검증(R3)은 **임시 git
repo**를 만들어 같은 함수를 돌린다:

| hermetic fixture | 기대 |
|---|---|
| 마커 줄(`<<<<<<< `·`>>>>>>> ` 각각) 가진 추적 텍스트 파일 | **검출**(rel·line 정확) |
| NUL 포함 + 첫 줄 마커인 추적 파일(임의 확장자) | 미검출(바이너리 스킵) |
| `workflow/REQ-2026-001/responses/x.json`에 마커 | 미검출(제외 경로) |
| 단독 `=======` 줄만 있는 텍스트 | 미검출(R2) |
| 미추적(untracked) 마커 파일 | 미검출(`ls-files` 수집 경계) |

실제 트리 검사(완료 기준 2)는 **같은 함수**에 이 저장소 루트를 먹인다 — 수집·판정·실검사가
전부 동일 경로다.
