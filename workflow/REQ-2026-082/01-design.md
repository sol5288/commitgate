# REQ-2026-082 설계 — 대문을 비개발자가 끝까지 따라올 수 있게 만든다

> 정본 결정은 SSOT(해당 DEC). 본 문서는 그 결정을 랜딩 README와 도움말 문자열에 어떻게 반영할지 기록.

## 현재 상태(변경 대상)

랜딩 `README.md`(182줄)의 골격:

```
# CommitGate → 히어로 이미지 → ## CommitGate란? (ASCII 33줄) → ## 무엇을 보장하고…
→ ## 준비물 → ## 3분 설치 → ## 첫 REQ 실행 → ## 사람이 멈추는 지점
→ ## 자주 쓰는 명령 → ## 더 알아보기 → ## License
```

내용의 **정확성·정직성은 유지 대상**이다(보장/비보장 표, 외부 전송 경고, 우회 가능 고지).
문제는 난이도가 아니라 **전제**다 — 설명 없는 용어가 20개 가까이 되고, 가장 어려운 문장이
`## 3분 설치` 바로 아래 있다. 그리고 **비용·복구·진단**이라는 비개발자의 3대 관심사가 전부 빠져 있다.

`bin/init.ts:1454-1482`의 도움말은 `init`·`migrate`·`uninstall` 3개만 안내한다.
실제 dispatch 가능한 verb는 `bin/dispatch.mjs`에 **16개**(`setup`·`check`·`sync`·`quickstart`·`delivery` 포함)다.

## 핵심 설계 결정

### DEC-1 — 🔴 비용을 **준비물 표에서** 말한다 (숨기지 않는다)

지금은 `codex --version`만 확인시킨다. 비개발자가 가장 먼저 묻는 "얼마 들어요?"에 대문이 답하지 않는다.

**어디에**: 준비물 표의 Codex CLI 행 — 링크 뒤로 미루지 않는다. 설치 **전에** 알아야 하는 정보다.

**무엇을**: 실측할 수 있는 사실만 적는다.

| 적는다 | 적지 않는다 |
|---|---|
| 리뷰는 Codex를 **실제로 호출**하므로 그 계정의 사용량·요금이 발생한다 | 🔴 구체적 금액·플랜명·토큰 단가 — **검증할 수 없고 바뀐다** |
| 로그인은 ChatGPT 계정 또는 OpenAI API 키 (실측: `check` C3 = `Logged in using ChatGPT`) | "저렴하다"·"거의 안 든다" 같은 평가 |
| 한 phase의 리뷰는 **무한정 돌지 않는다** — 자동 5회 / 6~8회는 사람 예외 / 9회부터 차단 | |

🔴 마지막 행이 DEC-1의 절반이다. 다이어그램의 `있다 ---> 위로 돌아가 다시 만든다` 화살표는
**무한 루프처럼 읽힌다** — 비용 이야기를 꺼낸 직후 상한을 말하지 않으면 겁만 주고 끝난다.
`reviewBudget` 기본값(`autoBudget: 5`·`hardCap: 8`)은 `docs/configuration.md:14`가 정본이고,
랜딩은 그 값을 **해석해서** 옮긴다.

### DEC-2 — 🔴 "승인 문장"은 **실물**을 보여준다

현재: *"통제점(`AWAIT_HUMAN`)에서 승인 문장을 줄 때만 개입하면 됩니다"*
→ 비개발자는 **뭐라고 타이핑해야 하는지 모른다.**

실제 값은 `req-next.ts`가 출력하는 짧은 문구다(예: `req:commit --run 승인`).
랜딩은 **주고받는 한 턴을 통째로** 보인다 — 에이전트가 뭘 물어보고, 내가 뭐라고 답하는지.

🔴 이 예시는 **실제 `req:next` 출력 형식**을 따른다(`req-next.ts:942` `승인 문장: "…"`).
형식을 지어내면 사용자가 실제 화면에서 그것을 못 찾는다.

### DEC-3 — 🔴 설치 커밋을 **실행 가능한 블록**으로 바꾸고 금지 이유를 붙인다

현재 `README.md:107`은 한 문장에 `clean 워킹트리`·`stage`·`-A`/`.`를 설명 없이 넣는다.
그리고 **왜 전체 stage가 위험한지**(민감정보가 딸려가 외부로 전송된다)는 quick-start에만 있다.

→ 랜딩에 **복사해서 칠 수 있는 3줄**과 **이유 한 줄**을 둔다.

🔴 이유를 함께 적는 것이 핵심이다. 이유 없는 금지는 지켜지지 않는다 —
비개발자는 막히면 가장 익숙한 `git add .`로 되돌아간다.

### DEC-4 — 🔴 시작 조건을 **행동**으로 바꾼다

`README.md:97`의 *"git 저장소이고 `package.json`이 있는 폴더에서"*는 **조건 서술**이다.
바이브코더의 폴더는 둘 다 없는 경우가 흔하고, 조건만 읽어서는 만족시키는 법을 모른다.

→ `git init` · `npm init -y` 두 줄을 **조건이 안 맞을 때 실행할 것**으로 명시한다
(quick-start `:6-8`에 이미 있는 내용을 랜딩으로 끌어올린다 — 새 사실이 아니다).

### DEC-5 — 🔴 **막혔을 때** 절을 신설하고 `check`를 1차 도구로 세운다

`npx commitgate check`는 **읽기 전용·아무것도 고치지 않고·어떤 게이트에도 배선되지 않은** 진단인데
(`docs/troubleshooting.md:62-63`) 랜딩에 **0회** 등장한다. 비개발자에게 가장 안전하고 쓸모 있는 명령이다.

가장 흔한 실패 3종에 **즉답**을 둔다 — 전부 이미 troubleshooting에 있는 사실이다.

| 증상 | 원인 | 조치 |
|---|---|---|
| `setup을 아직 마치지 않았습니다` | 신규 설치에서 3단계 미완 | `npx commitgate setup` (사람이 터미널에서 직접) |
| 리뷰가 `codex 종료 코드 1`로 죽는다 | 미설치·미로그인이 흔하다 | 🔴 **다시 돌리기 전에** `npx commitgate check` — 그 실패는 리뷰 예산을 차감한다 |
| `req:new`가 막힌다 | 워킹트리가 clean이 아니다 | 설치분 커밋(DEC-3 블록) |

🔴 두 번째 행의 "다시 돌리기 전에"가 요점이다(`docs/troubleshooting.md:50-52`).
비개발자의 기본 반응은 **재시도**인데, 이 실패는 재시도할 때마다 예산을 깎는다.

### DEC-6 — 명령표에 **비-`req:` 명령 행**을 추가한다

현재 표는 `req:*` 5개뿐이라, 사용자가 쓸 수 있는 명령이 그게 전부처럼 보인다.
`check`(진단) · `setup`(설정) · `sync`(자산 동기화) · `uninstall`(제거 계획)을 **두 번째 표**로 분리한다.

🔴 두 표를 나누는 이유: 호출 방식이 다르다. `req:*`는 `npm run … --` **스크립트**이고,
나머지는 `npx commitgate <verb>` **직접 실행**이다. 한 표에 섞으면 그 차이가 지워진다.

### DEC-7 — 🔴 `--help`를 dispatch 테이블과 **정합**시키고 회귀로 고정한다

README가 setup을 "🔴 건너뛸 수 없다"고 하는데 `--help`는 그 존재를 모른다.
터미널에서 `--help`부터 치는 사용자는 **필수 단계를 모른 채 진행한다.**

두 가지를 고친다:

1. **사용법 블록**에 `setup`·`check`·`sync`·`quickstart`·`delivery`를 등록한다.
2. **"설치 후" 순서**에 setup을 넣는다 — 현재 `1. codex 확인 → … → 4. 첫 티켓 생성`은
   🔴 **막힐 순서다**(setup 없이 `req:new`는 차단된다).

**회귀 가드**(`tests/unit/init.test.ts`): `VERB_MODULES`의 **비-`req:` 키가 전부** 도움말 문자열에
등장하는지 단언한다. 두 아티팩트(dispatch 테이블 · 도움말 리터럴)를 **교차 검증**하는 것이라
tautology가 아니다 — 새 verb를 등록하고 도움말을 잊으면 그 시점에 실패한다.
`req:*`는 제외한다(npm 스크립트로 호출되며 워크플로 문서가 정본).

### DEC-8 — 용어는 **접이식 사전** 한 곳에 모은다

`staged diff`·`phase`·`REQ 티켓`·`devDependency`·`fail-closed`·`delivery set`·`AWAIT_HUMAN`·`main 병합`.

`<details>` 안에 둔다 — 🔴 **아는 사람의 읽기 흐름을 끊지 않으면서** 모르는 사람에게 출구를 준다.
본문에 각주를 흩뿌리면 양쪽 모두에게 나쁘다.

### DEC-9 — 🔴 안전 4문구의 **위치·바이트를 건드리지 않는다** (제약)

`tests/unit/readme-landing.test.ts:80-90`이 4문구 각각의 첫 등장이 `## 3분 설치`보다
**앞**임을 단언한다. 이 REQ는 그 불변식을 **강화만** 한다:

- 4문구 자체 — 바이트 그대로 유지(재작성 금지).
- 보장/비보장 표 — 설치 **앞**에 그대로 둔다.
- ⚠️ 경고 2건 — 설치 앞에 그대로 둔다. 🔴 **`<details>`로 접지 않는다.**
  점검 단계에서 접는 안을 검토했으나 기각한다: 외부 전송·우회 가능은 **설치 전에 반드시 읽혀야 하는**
  사실이고, 접는 것은 읽히지 않는 것과 같다. 대문의 무게보다 이 두 사실이 무겁다.

### DEC-10 — 🔴 싣는 터미널 출력은 **실제 실행 결과**만

`check` 출력 예시는 이 저장소에서 실측한 것을 쓴다:

```
[OK] C1: req.config.json 유효(또는 부재 — 기본값 사용)
[OK] C2: 리뷰어 CLI 확인: codex-cli 0.144.1
[OK] C3: 리뷰어 로그인 확인: Logged in using ChatGPT
[OK] C4: 리뷰 모델·추론강도 고정: gpt-5.6-terra / medium
PASS — OK 4 · WARN 0
```

🔴 지어낸 출력은 사용자가 자기 화면과 대조할 때 **틀린 기대**를 만든다.
스크린샷 이미지 대신 텍스트 블록을 쓰는 이유: npm 페이지·터미널·다크모드에서 모두 깨지지 않고,
`assets/`에 유지 부담을 더하지 않는다.

🔴 **버전 문자열은 노후한다** — `codex-cli 0.144.1`·`gpt-5.6-terra`는 환경·시점마다 다르다.
블록 옆에 **"버전·모델 이름은 환경마다 다릅니다"**를 한 줄 붙여, 사용자가 자기 화면의 다른 숫자를
**고장으로 오해하지 않게** 한다. 읽어야 할 것은 숫자가 아니라 `[OK]`/`PASS` 형태다.

### DEC-13 — 🔴 쉽게 쓰되 **과잉 약속으로 흐르지 않는다**

이 REQ의 가장 큰 자충수 위험이다. "비개발자도 알아듣게"를 좇으면 조건절이 먼저 잘려 나가고,
남은 문장이 **실제보다 강한 보장**이 된다. REQ-2026-073이 정확히 그 실수를 리뷰에서 지적받았다
(과잉 약속을 고치는 REQ가 같은 종류의 과잉 약속을 새로 썼다 — `docs-stale-claims.test.ts:52-64`).

| 쓰면 안 되는 방향 | 이유 |
|---|---|
| "사람 확인 없이는 커밋되지 않습니다" | 🔴 **금지 문자열**이다. 기본값 `req`에서 HIGH 티켓의 중간 phase는 Codex 승인만으로 커밋된다 |
| "안전하게 지켜 줍니다" 류의 포괄 표현 | 무엇을 막고 무엇은 못 막는지가 이 도구의 값어치인데 그걸 지운다 |
| 우회 가능·외부 전송을 완곡하게 | DEC-9가 금지 |

→ **주어를 살린다.** "막아 줍니다"가 아니라 "**Codex 리뷰가 통과시키기 전에는** 커밋이 막힙니다".
쉬운 문장은 짧은 문장이지 **조건이 지워진 문장이 아니다.**

구현 후 `npm test`가 `docs-stale-claims`로 이 축을 기계 검증한다(고정 문자열 한정).

### DEC-11 — 탐색 UI: 목차 대신 **독자 분기**

182줄 9섹션에 진입점이 하나뿐이다. 다만 GitHub은 자동 TOC를 제공하므로 **긴 목차는 중복**이다.
상단에 **3갈래 바로가기** 한 줄만 둔다 — "빨리 써보고 싶다 / 뭘 보장하는지부터 / 막혔다".

배지에 **Node 20+**를 추가한다 — 0.12.0이 Node 18을 지원 범위에서 뺐고
(`docs/troubleshooting.md:4`), 배지 한 개가 값싼 사고 예방이다.

ASCII 다이어그램은 **유지**한다 — npm 패키지 페이지는 mermaid를 렌더링하지 않는다.
다만 33줄은 첫 화면을 다 먹으므로 세로를 압축한다(내용·순서 불변).

### DEC-12 — 되돌리기를 **본문에서** 한 줄 말한다

겁먹은 초보에게 "지울 수 있다"는 사실은 안심 장치다. 현재는 `## 더 알아보기` 표의 링크뿐이다.
설치 절 끝에 한 줄 — 제거 계획을 **미리 볼 수 있다**는 것까지(`uninstall`은 아무것도 지우지 않고 계획만 출력).

## 하위호환·안전

- 🔴 **코드 동작 불변** — 유일한 코드 변경은 `bin/init.ts`의 **도움말 문자열**이다. dispatch·게이트·보장 계약 무변경.
- 🔴 **안전 4문구·보장 표·경고 2건의 위치와 바이트 유지**(DEC-9). `readme-landing.test.ts`가 정본 가드.
- 🔴 docs 링크는 **절대 blob URL** — 상대 링크는 npm 페이지에서 깨진다(`readme-landing.test.ts:35-46`).
- 🔴 **보장을 약화하지도, 과장하지도 않는다**(DEC-13). 무르게 하는 것과 조건을 지우는 것은 **둘 다 실패**다.
  `tests/unit/docs-stale-claims.test.ts`의 금지 문자열이 기계 가드다.
- 비용 진술은 **검증 가능한 것만**(DEC-1) — 금액·플랜명을 적지 않아 가격 변동에 썩지 않는다.
- 링크는 `npm run docs:lint`(`remark-validate-links`)가 검증한다.
