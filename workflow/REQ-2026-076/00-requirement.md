# REQ-2026-076 요구사항 — 교착한 CI 잡이 빨리 죽고 로그를 남기게 한다

## 왜 지금인가

2026-07-27, `macos-latest · node 18`의 `npm test`가 두 번 교착했다. 그 결과 세 가지 실해가 있었다.

1. 🔴 **로그를 볼 수 없었다.** GitHub는 **진행 중인 잡의 로그를 주지 않는다**(`gh run view --log` →
   "still in progress"). 원인을 보려면 잡을 **죽여야 했다** — 진단하려면 증거를 없애야 하는 상태였다.
2. 🔴 **릴리스 CI를 막았다.** REQ-2026-075가 넣은 `concurrency`는 `main`에서 `cancel-in-progress: false`라
   새 실행이 앞 실행 **뒤에 큐잉**된다. 교착한 잡 하나가 0.11.0 릴리스 커밋의 CI를 통째로 세웠고,
   사람이 손으로 중지해서 풀어야 했다.
3. **기본 타임아웃이 360분**이다. 아무도 손대지 않으면 6시간을 점유한다.

## 실측 (2026-07-27)

| 항목 | 값 |
|---|---|
| 잡 최장 소요(정상) | windows **7.0분** · macos 2.4분 · ubuntu 1.1분 |
| 교착 관측 ① `86548e2` | macos node18 — **35분+** 후 사람이 취소 |
| 교착 관측 ② `a368a77` | macos node18 — 13.6분+ 후 사람이 취소 |
| 현재 `timeout-minutes` | **없음** → GitHub 기본 **360분** |
| 교착 시 로그 | **취득 불가**(잡 종료 후에만 가능) |

🔴 교착 ①은 `fileParallelism: false`(전면 직렬) 상태에서 났다 — REQ-2026-044의 해결이 이 실패 모드를
없애지 못했다는 뜻이고, 병렬화(REQ-075)와도 무관하다.

## 수용 기준

1. 잡이 교착하면 **정상 소요의 몇 배 안에서 실패로 끝난다** — 6시간을 점유하지 않는다.
2. 🔴 **정상 실행을 죽이지 않는다.** 상한은 최장 잡(windows 7.0분)에 **충분한 여유**를 둔다.
   러너 성능 변동·npm 레지스트리 지연으로 정상 실행이 타임아웃되면 **CI가 거짓 red를 내는 것**이고,
   그건 지금 문제보다 나쁘다(사람이 red를 무시하기 시작한다).
3. 🔴 **로그가 남는다.** 타임아웃으로 종료된 잡의 로그를 `gh run view --log`로 받을 수 있어야 한다 —
   이 REQ의 두 번째 목적이 **후속 근원 원인 조사의 진단 수단**을 만드는 것이다.
4. 문서가 그 값과 **왜 그 값인지**를 말한다.

## 범위 밖

- 🔴 **macos node 18 교착의 근원 원인** — 별도 REQ. 이 REQ는 그 조사를 가능하게 만들 뿐 고치지 않는다.
  (로그 실측: 테스트 출력이 끊긴 뒤 정리 단계에서 `Terminate orphan process: pid (2040) (esbuild)`.
  macOS는 arm64, Node 18은 EOL.)
- 매트릭스에서 node 18 제외 — 지원 범위 축소이고 required checks 이름이 바뀐다(사용자 통제점).
- `concurrency`의 큐잉 동작 변경 — main을 취소 대상에서 뺀 것은 **의도된 설계**다(direct push 사후
  검증 기록 보존). 교착이 큐를 막는 것은 타임아웃으로 푼다.
