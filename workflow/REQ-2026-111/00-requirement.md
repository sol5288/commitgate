# REQ-2026-111 요구사항

게이트 관측성 — doctor 결과를 append-only 로그로 남긴다

## 무엇을 / 왜

`req:doctor`가 실행한 D-체크의 판정 결과를 **로컬 append-only 로그**로 남긴다.

**왜 필요한가 — 실측:**

- 등록부 `D_CHECK_IDS`(`scripts/req/req-doctor.ts:80`)에 **22개** 검사가 있고, 그중 **10개가 FAIL 가능**
  (D2·D3·D6·D9·D10·D11·D13·D15·D16·D17), 나머지 12개는 WARN 전용이다.
  (0.19.0 기준. D5는 REQ-2026-108이 FAIL→WARN으로 낮췄고, D28은 REQ-2026-110이 WARN으로 신설했다.)
- 그런데 `req-doctor.ts`에는 결과를 남기는 코드가 **하나도 없다**
  (`writeFileSync`/`appendFileSync` 0건). 판정하고 출력하고 사라진다.
- 소비자 저장소 3곳(271티켓·16일)을 전수 조사해도 doctor 결과가 축적된 파일이 **없다**.

그 결과 **"어떤 검사가 실제로 무엇을 막았는가"를 아무도 답할 수 없다.**
같은 조사에서 발화가 실측된 게이트는 3개뿐이었다 — 리뷰 게이트(2,088호출 중 48.5% 차단),
응답 구조 게이트(invalid 10건), 리뷰 예산 게이트(사람 예외 129건). 이 셋은 각자 로그를 남기기 때문이다.

> **로그를 남기는 게이트만 값어치를 증명할 수 있었다.** 나머지는 "잘 막고 있다"는 믿음만 있다.

이 상태에서 검사를 더하거나 빼면 **근거 없이 더하거나 근거 없이 빼는 것**이 된다.

## 제약

1. 🔴 **관측이 판정을 바꾸면 안 된다.** 로그 기록의 성공·실패와 무관하게 `req:doctor`의
   출력·FAIL 개수·exit code가 동일해야 한다. 로깅은 게이트가 아니다.
2. 🔴 **로그는 커밋 대상이 아니다.** 소비자 저장소에서 untracked 파일이 생기면 D10(워킹트리 클린)이
   FAIL한다. gitignore가 **루트와 배포 템플릿 양쪽에** 있어야 한다.
3. 기존 D-체크의 판정 로직·메시지·level을 바꾸지 않는다.
4. 외부 전송 없음. 로컬 파일뿐이다.
5. 로그에 프롬프트·diff·finding 본문 같은 **내용**을 담지 않는다. 판정 결과(id·level)만 담는다.

## 완료 기준

| # | 기준 | 검증 방법 |
|---|---|---|
| AC-1 | 실제 진입점 `main()` 1회 실행이 로그에 **1행**을 append한다 | hermetic repo에서 `doctorMain()` 실행 후 파일 내용 확인 |
| AC-2 | FAIL/WARN이 난 검사의 `id`·`level`이 그 행에 담긴다 | FAIL이 나는 상태를 구성해 행 내용 대조 |
| AC-3 | 로그 기록이 실패해도 **출력과 exit 동작이 동일**하다 | 기록 경로를 쓰기 불가로 만들고 두 실행의 출력·exit 비교 |
| AC-4 | 루트 `.gitignore`와 `templates/workflow.gitignore` **양쪽**에 규칙이 있다 | 두 파일 모두 검사(한쪽만 있으면 실패) |
| AC-5 | D22의 스크래치 목록에 새 경로가 포함된다 | 목록에 없으면 실패하는 테스트 |

## 비목표

- **doctor 판정 로직의 변경** — 이 REQ는 관측만 추가한다.
- **로그를 커밋하거나 감사 증거로 승격** — 별건이다. 커밋하면 커밋 소음과
  브랜치-지역 유실 문제를 물려받는다(설계 DEC-1 참조).
- **체크별 "평가됨" 여부의 완전한 기록** — 이번에는 `evaluated` 개수만 남긴다(설계 DEC-3).
- **로그 회전·상한·정리 명령** — 행이 실행당 1개라 당장 필요하지 않다. 필요해지면 별건.
- **수집한 로그를 분석하는 명령/리포트** — 파일이 먼저 있어야 한다.
- 외부 텔레메트리.

## 대표 예시 (정상 경로)

```
$ npm run req:doctor -- 2026-111
[req:doctor] OK D2: branch 일치
[req:doctor] WARN D18: granularity ...
[req:doctor] FAIL D10: unstaged/untracked 존재 ...
[req:doctor] FAIL 1건 (REQ=REQ-2026-111)
```

실행 후 `workflow/.doctor-runs.jsonl`에 1행:

```json
{"ticket_id":"REQ-2026-111","at":"2026-08-02T00:00:00.000Z","verdict":"FAIL","evaluated":22,"nonok":[{"id":"D18","level":"WARN"},{"id":"D10","level":"FAIL"}]}
```

## 예외·실패

| 상황 | 동작 |
|---|---|
| 로그 디렉터리 생성 실패 | 조용히 무시. doctor 판정 그대로 진행 |
| 파일 쓰기 권한 없음 | 조용히 무시. doctor 판정 그대로 진행 |
| 디스크 가득 참 | 조용히 무시. doctor 판정 그대로 진행 |
| 로그가 gitignore되지 않음 | **D22가 이미 WARN한다**(기존 검사 재사용) |

## 용어

- **D-체크**: `req:doctor`가 실행하는 일관성 검사. 등록부 `D_CHECK_IDS`가 정본.
- **non-OK**: level이 `FAIL` 또는 `WARN`인 검사 결과.
- **관측 로그**: 판정에 관여하지 않고 사실만 남기는 로컬 파일. `workflow/.review-calls.jsonl`이 선례.

없음. 저장 위치·행 단위·실패 처리는 설계에서 확정한다(DEC-1~DEC-4).
