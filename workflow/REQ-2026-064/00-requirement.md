# REQ-2026-064 요구사항

원장 하위호환 계약 + 모델·effort·provider 감사 기록

## 배경

`commitgate setup`(REQ-2026-060)이 리뷰 모델·추론강도를 **쉽게 바꿀 수 있게** 만들었다.
그런데 **커밋되는 감사 기록에는 어떤 모델이 리뷰했는지가 없다**:

| 기록처 | 모델 | 커밋됨 |
|---|---|---|
| `.review-calls.jsonl` | O (REQ-2026-043) | **X — gitignore, 측정 전용** |
| `review-ledger.jsonl` (REQ-2026-051) | **X** — `LEDGER_KEYS`에 부재 | O |
| `approvals.jsonl` / 아카이브 매니페스트 | X | O |

그래서 모델을 바꿔 가며 리뷰하면 **fresh clone에서 "어느 모델이 이 phase를 승인했는가"를 알 수 없다.**
이 갭은 setup 이전에도 있었지만(손으로 파일을 고치면 같다), setup이 그 경로를 상용화하므로
**REQ-2026-060은 이 REQ와 같은 릴리스로 나가야 한다**(그 REQ의 `00-requirement.md` 제약).

## 🔴 선행 결함 — 원장 스키마는 지금 확장할 수 없다

`review-ledger.ts`의 주석은 *"릴리스 후 스키마 변경은 additive-only여야 한다"* 고 하는데,
**검증기가 그 additive를 실제로는 허용하지 않는다**:

```js
for (const k of LEDGER_KEYS) if (!(k in r)) p.push(`필수 키 누락: ${k}`)
```

허용 키 목록과 필수 키 목록이 **같은 배열**이라, 키를 하나 추가하는 순간 **이미 커밋된 모든 원장 행이
"필수 키 누락"으로 거부**되고 D5 fail-closed가 그 티켓의 리뷰를 전부 막는다.
0.9.10이 배포됐으므로 **야생에 옛 원장이 있다.**

## 요구사항

| # | 내용 |
|---|---|
| **R1** | 원장 스키마를 **하위호환 가능하게** 만든다 — 신규 키 추가가 기존 커밋된 원장을 깨뜨리지 않는다 |
| **R2** | 리뷰 호출의 **모델·추론강도·provider**를 커밋되는 원장에 기록한다 |
| **R3** | 기록 값의 원천은 `.review-calls.jsonl`과 **동일**해야 한다(두 기록이 갈라지지 않는다) |

## 🔴 하위호환 계약 (R1의 구체)

1. **과거 행은 신규 키 부재를 허용한다.**
2. **새 행은 신규 키를 항상 직렬화한다**(값이 `null`이어도 키는 존재).
3. **존재하는 optional 값은 엄격 검증한다**(있는데 타입이 틀리면 거부).

## 🔴 정직성 경계

기록하는 모델은 **"CommitGate가 이 요청에 핀한 모델"**이지 **"codex가 실제로 실행한 모델"이 아니다.**
`.review-calls.jsonl`의 기존 경계와 같다(`review-codex.ts`: *"codex가 실제 실행한 모델을 주장하지 않는다"*).
이름과 문서가 그 차이를 분명히 해야 한다.

## 🔴 비목표

| 비목표 | 이유 |
|---|---|
| **`approvals.jsonl`·아카이브 매니페스트 확장** | 원장 하나로 충분하다. 여러 곳에 같은 사실을 쓰면 갈라진다(REQ-2026-051의 "approvals를 중복하지 않는다" 원칙) |
| **provider 추상화** | provider는 현재 codex 하나다. 이 REQ는 **값을 기록**할 뿐 provider 교체를 만들지 않는다 |
| **`.review-calls.jsonl` 변경** | 이미 기록하고 있다. 이 REQ는 커밋되는 쪽을 맞춘다 |

## 수용 기준

1. `LEDGER_KEYS`에 신규 키를 넣어도 **기존 커밋된 원장 행이 그대로 통과**한다.
2. 새로 쓰는 행은 신규 키를 **항상 포함**한다(값이 `null`이어도).
3. optional 키가 있는데 타입이 틀리면 **거부**한다.
4. `attempt-opened`·`attempt-closed` 양쪽에 모델·effort·provider가 기록된다.
5. 기록 값이 `.review-calls.jsonl`의 값과 **같은 원천**에서 온다.
6. `npm test` green · `tsc --noEmit` 0.
