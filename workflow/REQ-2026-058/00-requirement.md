# REQ-2026-058 요구사항

## 무엇

Nuxt 소비자 감사(2026-07-25)에서 나온 **안내·진단 계층 결함 7건**을 한 번에 정리한다.
게이트 의미론·승인 규칙은 건드리지 않는다 — 전부 "도구가 사람에게 무엇을 말하는가"의 문제다.

| # | 결함 | 등급 |
|---|---|---|
| F-3 | 사람 승인 경로의 `req:next` RUN 명령을 그대로 실행하면 커밋 메시지 누락으로 실패한다 | P2 |
| F-5 | 정상 상태(HEAD에 증거가 아직 없음)에서 raw `fatal: path … does not exist in 'HEAD'`가 표출된다 | P2 |
| F-6 | 제거 계획이 권하는 도입 커밋 revert가 `workflow/.gitignore`를 함께 지워 티켓 scratch가 노출되는데, 그 파급을 예고하지 않는다 | P2 |
| F-4 | 설치 안내의 lockfile 인과 설명("2단계 install이 lockfile을 만든다")이 Stage B 흐름과 맞지 않는다 | P3 |
| F-7 | 제거 계획 §6이 Stage B에 존재하지 않는 `scripts/`를 잔여 후보로 안내한다 | P3 |
| F-8 | `not-installed` 판정에서 남아 있는 감사 증거(`workflow/REQ-*`)를 알리지 않는다 | P3 |
| F-9 | `_npx` 캐시 삭제 안내가 **사용자의 모든 npx 패키지 캐시**를 지운다는 사실을 밝히지 않는다 | P3 |

## 왜

이 도구의 계약은 "다음 행동을 추측하지 말고 `req:next` 출력을 그대로 실행하라"이고, 제거 계획은
"이 명령들을 직접 실행하라"고 지시한다. **출력이 곧 실행 계약**인데 그것이 실패하거나(F-3),
정상 상태를 실패처럼 보이게 하거나(F-5), 실행 결과를 예고하지 않으면(F-6·F-9) 계약이 무너진다.

## 완료 기준

1. `req:next`가 AWAIT_HUMAN에서 출력하는 `req:commit` 명령을 **그대로 실행하면 메시지 누락으로 죽지 않는다**
   (자리표시자 포함 — LOW 자동 커밋 경로가 이미 쓰는 형식과 동일).
2. 증거가 아직 HEAD에 없는 정상 상태에서 `req:next`·`req:review-codex`·`req:commit`이
   **raw git `fatal:`을 표출하지 않는다.** 그 조회의 판정 결과(없으면 null)는 그대로다.
3. `commitgate uninstall` 계획이:
   - 도입 커밋 revert가 `workflow/.gitignore`를 함께 되돌려 기존 티켓 scratch가 노출될 수 있음을 **예고**하고
     보존/정리 선택지를 제시한다(F-6).
   - Stage B에서 만들지 않는 `scripts/`를 잔여 후보로 나열하지 않는다(F-7).
   - `not-installed`일 때도 남아 있는 티켓 증거를 고지한다(F-8).
   - `_npx` 삭제가 **모든** npx 패키지 캐시를 지운다는 범위를 명시한다(F-9).
4. 설치 안내의 lockfile 문구가 Stage B 사실과 일치한다(F-4).
5. 전체 테스트 green.

## 제약

- 게이트 판정·승인 규칙·exit code를 바꾸지 않는다. 문구·진단 출력·안내만 바꾼다.
- `fatal:` 억제는 **그 조회의 결과 판정을 바꾸지 않는다** — 여전히 "HEAD에 없음 → null"이다.
  다른 git 호출의 진단은 계속 보여야 한다(전역 stderr 억제 금지).

## 비목표

- P1(durable state checkpoint) — REQ-2026-057에서 이미 처리했다.
- 제거의 자동 실행(planner는 읽기 전용을 유지한다).
- 문서(`docs/*.md`) 전면 개편 — 이번엔 도구 출력과 그에 직접 대응하는 문서 문장만 다룬다.
