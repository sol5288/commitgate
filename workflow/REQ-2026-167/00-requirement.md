# REQ-2026-167 요구사항

## 무엇

업그레이드 문서(`docs/upgrade.md`·`.en.md`)와 README 의 업그레이드 구역이 **실제로 절차를 끝까지
안내하도록** 고친다. 지금은 문서를 그대로 따라가도 **끝나지 않은 상태에서 끝난 줄 안다**.

## 왜 — 실측

0.22.0 설치본을 만들어 0.25.1 로 올리는 전 과정을 샌드박스에서 수행했다. 문서가 시키는 대로 했을 때
어디서 멈추는지가 그대로 드러났다.

| 단계 | `C7` |
|---|---|
| 0.25.1 설치 직후 | 조치 **3** (`req-scripts` · `managed-blocks` · `contract-claims`) |
| `sync --apply --scripts --gitignore` + `quickstart --apply` | 조치 **1** |
| `contract-claims` 수동 병합 **1회** | 조치 **1** — 🔴 **줄지 않았다** |
| 수동 병합 **2회** | 조치 **0** · WARN 0 |

### ① 폐기 서술은 **여러 자리**에 있고, 문서는 한 번이면 끝나는 것처럼 적혀 있다

실측한 `AGENTS.md`:

- `79` — `통합(main 병합) 승인은 어느 값에서도 필요하다`
- `57` — `통합 승인은 stopGate 값(phase/req/merge)과 무관하게 항상 존재` ← **다른 절**

첫 번째를 고치고 `check` 를 다시 돌리면 두 번째가 나온다. 현행 문서는

> `C5` 가 **찾은 문장을 그대로** 보여 주므로 그것만 손으로 병합하세요.

라고만 적어, **한 번 고치면 끝**으로 읽힌다. 실제로는 `check` 가 조용해질 때까지 반복해야 한다.

### ② 인용된 문장을 그대로 `grep` 하면 안 잡힌다

`retiredClaimsIn` 은 대조 전에 `normalizeForClaimScan` 으로 **마크다운 강조·코드 표시(`*` `_` `` ` `` `~`)를
제거하고 공백을 압축**한다(`retired-claims.ts:359`). 그래서 `check` 가 인용하는 문장과 파일의 실제 바이트가
다르다. 실측:

```
$ grep -n "무관하게 항상 존재" AGENTS.md     → (없음)
$ grep -n "무관하게" AGENTS.md               → 57: - 통합 승인은 `stopGate` 값(`phase`/`req`/`merge`)과 무관하게 **항상** 존재하므로 …
```

문서 어디에도 이 함정이 없다. 사용자는 "인용된 문장이 파일에 없다"는 상태에서 멈춘다.

### ③ 언제 끝났는지가 문서에 없다

현행 "정리" 한 줄:

> `commitgate@latest` 설치 → `sync --apply --scripts` → `quickstart --apply` → `check`(C5·C6 확인) → (필요 시) `migrate`

- `check` 가 **맨 뒤**에 있다. 실제로는 **무엇을 할지 정하는 진단**이라 앞에 와야 한다.
- `--gitignore` 가 빠져 있다.
- **수용 기준이 없다.** 무엇이 되면 끝인지 적혀 있지 않아, 조치가 남아 있어도 "명령을 다 쳤으니 끝"이 된다.

### ④ README 의 요약 명령 하나로는 업그레이드가 끝나지 않는다

README 의 업그레이드 구역은 `npx commitgate sync --apply --scripts --gitignore` 하나만 보여 준다
(`UPGRADE_SUMMARY_COMMAND`). 실측에서 그 명령만으로는 `managed-blocks`·`contract-claims` 가 남았다.
**진입점은 진단(`check`)이어야 한다** — 무엇을 실행할지는 축마다 다르고, 그것을 아는 것은 도구다.

### ⑤ 도구가 보지 않는 축이 문서에 없다

`sync` 는 스스로 *"companion skills · req.config.json 은 건드리지 않습니다"* 라고 말한다. 그런데
`check` 도 그 축을 보지 않는다. 즉 **어느 진단에도 걸리지 않는 자산**이 있는데 문서에 확인 방법이 없다.
(0.22.0 → 0.25.1 구간에서는 실제 차이가 없었다 — 이번 판은 운이 좋았을 뿐이다.)

## 완료 기준

1. 정본 문서(`docs/upgrade.md`·`.en.md`)가 다음을 담는다.
   - **진단 먼저**: `check` 가 절차의 시작이라는 것.
   - **반복까지가 절차**: `contract-claims` 는 `check` 가 조용해질 때까지 반복.
   - **검색 함정**: 강조 문자를 뺀 조각으로 찾아야 한다는 것(근거 = 정규화).
   - **수용 기준**: `C7` 조치 0 (`caret-range` 의 "사람 확인"은 남아도 된다).
   - **도구가 보지 않는 축**: companion 자산 대조 방법.
2. README(ko/en)의 업그레이드 구역이 **진단 명령**을 진입점으로 보여 준다.
3. 위 서술이 문서 양쪽(ko/en)에 **둘 다** 있음을 가드가 고정한다.
4. 변경한 소스를 import 하는 테스트 그린 · 통합 직전 전체 스위트 1회 그린.
