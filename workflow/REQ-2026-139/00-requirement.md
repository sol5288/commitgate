# REQ-2026-139 요구사항

## 무엇을

이 저장소(`req.config.json`)의 리뷰 예산 정책을 `onSoftLimit: "auto"`로 채택한다.

```json
"reviewBudget": { "autoBudget": 5, "hardCap": 8, "onSoftLimit": "auto" }
```

## 왜

이 저장소는 `stopGate: "merge"`로 자율 진행을 고르고도, 리뷰 예산 축이 기본값 `ask`라서 소프트 한도를
넘긴 회차마다 사람 예외 승인에서 멈췄다. REQ-2026-135가 만든 업그레이드 안내가 가리키는 바로 그 상태다.

**이것은 비용 정책 결정이다.** `auto`가 없애는 것은 소프트 초과 회차의 **사람 예외 승인 하나뿐**이고,
그 대가로 6~8회차가 사람 확인 없이 유료 호출을 쓴다.

## 제약

- 🔴 **`hardCap`을 늘리거나 없애지 않는다.** `auto`는 소프트 한도의 사람 확인만 없애고 반복 백스톱은
  그대로 둔다 — `hardCap`은 비용 상한이 아니라 **무한 루프 방지**이며, 이 값을 건드리면 `auto`가
  "무제한 자동"이 된다.
- 기본값과 같은 값(`autoBudget: 5`·`hardCap: 8`)을 **명시적으로 적는다.** 이 저장소가 어떤 예산으로
  도는지 설정 파일만 보고 알 수 있어야 한다.
- 이 REQ는 **도구 동작을 바꾸지 않는다.** 소비자 기본값은 여전히 `ask`다.

## 완료 기준

- `req.config.json`이 스키마를 통과한다.
- `stopGate: "merge"` + `onSoftLimit: "auto"`에서 소프트 한도 초과가 `AWAIT_HUMAN`을 만들지 않음을
  **기존 회귀 테스트**로 확인한다(새 테스트를 만들어 증명하지 않는다 — 이미 있다).
- `hardCap` 도달은 **두 값 모두에서** 여전히 막힘을 확인한다.
- `npm run typecheck` · `npm run docs:lint`.
