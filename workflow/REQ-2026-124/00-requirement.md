# REQ-2026-124 요구사항

commitgate report — 로컬 관측 요약(읽기 전용)

## 배경

관측 데이터는 이미 로컬에 쌓인다 — `.doctor-runs.jsonl`(REQ-2026-111·117 subjects),
`.review-calls.jsonl`(REQ-2026-025·045·113·118), `.verify-runs.jsonl`(REQ-2026-116) — 그러나
**요약할 수단이 없다.** 이번 세션의 모든 재검증(발화 분포·수렴 라운드·CI 선택)이 일회성 node
스크립트 손집계였다. 도구가 심은 관측을 도구가 읽지 못하면 관측의 절반은 죽어 있는 것이다.

## 요구

- **R1 · verb `report`** — 읽기 전용·비대화형·어떤 게이트에도 비배선(`check`와 같은 지위).
  `--json`(기계용)·`--dir`(대상 repo). 네트워크·유료 호출 없음.
- **R2 · 섹션과 원천** (각 섹션은 원천 파일이 없으면 "데이터 없음"을 표기한다 — 추정 금지):
  1. **doctor**: 실행 수·티켓 수·검사별 발화/FAIL 수·WARN-only 실행 비율·**해소 관측**
     (subjects 있는 검사에 한해, 과거에 발화한 (검사, subject)가 최신 실행에서 사라졌으면 해소로
     센다 — REQ-2026-117이 연 축).
  2. **review**: (티켓, 종류, phase)별 호출 수 분포(중앙값·최대 — "시리즈당"이 아니라 "대상당
     총 호출"로 정직하게 명명: archive_round는 시리즈 리셋이 없다)·outcome 비율·델타 모드 비율·
     `full_review_reason` 분포·prompt_bytes p50/p95·리뷰 소요 p50/p95.
  3. **evidence**: trunk 대비 커밋 범위의 verify-range 요약(승인 소비/부기/머지/미입증 —
     REQ-2026-116 코어 재사용)·doctor 최신 실행의 D25/D30 발화 subjects.
  4. **ci**: `.verify-runs.jsonl`의 CI 선택 분포(기본 생략/명시 생략/확인 성공/확인 실패).
- **R3 · 정직한 명명** — "검사별 적용 가능 수"는 기록되지 않으므로(런로그는 발화만 담는다)
  **제공하지 않고 그 사실을 출력에 명시**한다. 손상 행은 건너뛰되 개수를 표기한다.
- **R4 · 표면** — `--help`·dispatch 등록(기존 정합 가드 준수), `docs/workflow.md`/`.en`에 한 절.

## 제약

- 어떤 상태·파일도 쓰지 않는다(로그 append조차 없음 — 순수 조회).
- 로그 내용 계약 유지: 출력에 경로·본문을 새로 노출하지 않는다(로그가 담은 id·개수·해시 요약만).
- 기존 로그 스키마 무변경(선택 키 부재 행 하위호환 그대로 소비).

## 완료 기준

1. 세 로그가 있는 repo에서 4섹션이 실측값으로 렌더링된다(fixture 로그 기반 단위 검증).
2. 로그가 하나도 없는 repo에서 각 섹션이 "데이터 없음"으로 표기되고 exit 0.
3. `--json`과 사람용 출력이 같은 집계 결과에서 파생된다(check.ts DEC-5 선례).
4. 손상 행 혼입 시 건너뛰고 개수를 표기한다(전체 실패 없음).
5. help↔dispatch 정합 가드 그린.
