# REQ-2026-074 계획 — phase 분해 (DEC-WF-027 §9.0)

설계 승인 후 phase별 진행. **각 phase 후 Codex 리뷰·승인 → 다음.**

> **Granularity 정책(REQ-2026-016 Phase C)**: phase 1개는 리뷰 가능한 크기로 — 코드 변경 8파일 이하 권고.

## Phase 1 — 한국어 랜딩 재구성 (`phase-1-readme-ko`)

범위(DEC-1~DEC-5): `README.md` 하나.

순서:
1. 산문 3절(15·23·32행)을 `## CommitGate란?` **한 절**로 합치고 **ASCII 흐름도**를 넣는다.
   - 그림은 ```text 코드블록 · 폭 **80자 이하**(GitHub·npm·터미널에서 접히지 않게).
   - 🔴 그림 아래 한 문단으로 **"승인된 그 tree만 커밋된다"** 계약을 남긴다(DEC-1) —
     그림은 호출 관계를 보여 줄 뿐 계약을 말하지 못한다.
   - 기존 대비표(25~30행)는 그대로 이 절 안에 둔다.
2. 39행(보장)과 47행(경고)을 `## 무엇을 보장하고, 무엇은 보장하지 않나` 한 절로 합친다.
   - 🔴 외부 전송 · git hook 부재 두 경고는 **표 밖 강조 블록**으로 유지한다(DEC-2).
     표 칸에 넣어 작아지면 안 된다.
3. `## 준비물` 신설 — Git · Node 18.17+ · 패키지 매니저 · Codex CLI + **확인 명령**.
   설치 방법은 넣지 않고 quick-start로 보낸다(DEC-3).
4. `## 사람이 멈추는 지점` 신설 — `stopGate` 세 값 표.
   🔴 확인 `scope`·HIGH 취급은 넣지 않고 정본 링크(DEC-4 · REQ-073 결정 유지).
5. 🔴 **삭제 점검**: companion skills · `/req` 예시 · 첫 응답 예시 · 명령표 · 문서 표가
   전부 남아 있는지 확인한다(DEC-5). 줄어드는 것은 같은 말의 반복뿐이어야 한다.
6. 링크는 **절대 blob URL** 유지 · 한글 앵커 사용 금지(`docs:lint` 미해석 — REQ-073 실측).

Exit: `docs:lint` green · 절 수 ≤ 11 · 수용기준 1~5·7 · Codex 승인.

## Phase 2 — 영문 랜딩 + CHANGELOG (`phase-2-readme-en`)

범위(DEC-6): `README.en.md` · `CHANGELOG.md`.

순서:
1. phase-1에서 확정된 **절 구성 그대로** 영문을 재구성한다.
   🔴 바이트 동일이 아니다 — 같은 절·같은 순서·같은 표 열이면 된다.
2. ASCII 흐름도는 **모양을 같게** 두고 라벨만 번역한다.
   🔴 라벨 길이가 달라 칸이 어긋나지 않게 폭을 다시 맞춘다(등폭 기준).
3. CHANGELOG에 랜딩 재구성을 적는다 — **정보 삭제가 아니라 재배치**임을 명시한다.

Exit: `docs:lint` green · 한/영 절 구성 일치 · 수용기준 6 · Codex 승인.
