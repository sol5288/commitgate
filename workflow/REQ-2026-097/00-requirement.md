# REQ-2026-097 요구사항

## 배경 — 소비자 버그 리포트(yammy-sales, 0.16.0)

**종결된 티켓에 `req:doctor`를 돌리면 항상 FAIL(exit 1)이다.** 브랜치를 병합하고 지우는 것은
권장 운영인데, 그 뒤 D2·D3·D11이 계속 발화한다.

리포터의 재현 절차를 이 저장소에서 그대로 실행해 재현했다(REQ-2026-072 — 종결·main 반영·브랜치 삭제됨):

```
[req:doctor] FAIL D2:  state.branch(feat/req-2026-072-close-predicate-parity) != current(main)
[req:doctor] FAIL D3:  state.branch 로컬에 없음: feat/req-2026-072-close-predicate-parity
[req:doctor] FAIL D11: REQ 작업이 자기 feature 브랜치 밖(current=main, state.branch=…)
[req:doctor] OK   D25: 종결 티켓이 모두 trunk(main)에 반영됨
[req:doctor] OK   D27: 승인 증인 일치
[req:doctor] FAIL 3건 (REQ=REQ-2026-072)   exit=1
```

리포터는 FAIL 4건을 봤고 여기는 3건이다 — 나머지 1건(D10)은 그 티켓과 무관한 워킹트리 변경 때문이며
리포터도 그렇게 밝혔다. 종결 티켓 전부에서 같은 결과가 난다(리포터 실측 118건).

## 도구는 이미 사실을 알고 있다

`req-doctor.ts`의 D25 수집부(:962-967)는 각 티켓의 close proof 존재를 이미 스캔한 뒤,
그 목록에서 **현재 티켓만 제외**해 D25에 넘긴다. 즉 "현재 티켓이 종결됐는가"는 계산 직전까지 갔다가
`runChecks`(:311)에 전달되지 않아 D2/D3/D11이 그것을 보지 못한다.

## 영향

- **`req:doctor`를 건강 점검으로 쓸 수 없다.** 과거 티켓을 점검하려면 exit 1을 무시해야 하므로
  스크립트·CI에 넣을 수 없다.
- **에이전트가 "복구"를 시도한다.** AGENTS.md 계약을 따르는 에이전트가 FAIL을 보고 종결 티켓의
  feature 브랜치를 되살리려 한다 — 명백한 오작동이다. 리포터 세션에서 실제로 그 판단을 한 번 했다.
- **신호가 죽는다.** 무관한 D10 FAIL이 이 세 건에 묻힌다.

## 요구사항

- **R1** — 종결이 검증된 티켓에서는 브랜치 동일성 축(D2·D3·D11)이 FAIL을 내지 않는다.
- **R2** — 종결 판정은 저장소의 **기존 종결 술어**를 재사용한다. 새 술어를 만들지 않는다
  (REQ-2026-072가 "종결 술어가 두 곳에서 갈라져 탈출구가 사라진" 사고를 이미 겪었다).
- **R3** — 워킹트리 축(D10·D13 등)은 그대로 둔다. 종결 여부와 무관한 사실이기 때문이다.
- **R4** — 완화가 **커밋 경로를 열어서는 안 된다.** 종결 티켓이 main에서 커밋 가능해지면 안 된다.
- **R5** — 미계산·판정불가·손상(`corrupt`)은 **종결로 보지 않는다**(fail-closed). 기존 동작이 기본값이다.

## 범위 밖

- D10의 노이즈 자체(무관한 워킹트리 변경)는 종결과 무관한 축이라 건드리지 않는다(R3).
- BUG-1(phase id 문자 집합)은 REQ-2026-096에서 이미 해결·통합됐다(main `4f3e10d`).
