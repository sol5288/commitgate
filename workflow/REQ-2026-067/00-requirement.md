# REQ-2026-067 요구사항 — `commitgate setup` 대화형 UI 개선

## 배경

0.10.0에서 `commitgate setup`이 배포됐고 사용자가 실제 소비자 프로젝트
(`D:\tmp\cg-install-audit-20260725\matjib-nuxt`)에서 실행해 정상 동작을 확인했다.
그 실행에서 나온 요구가 이 REQ의 입력이다.

현재 setup은 `node:readline/promises`의 `question()`으로 **한 줄 자유 입력**을 받는다.
enum 값이 있는 질문도 선택지를 **문자열로 나열**하고 사용자가 그 값을 타이핑한다.

```
사람이 멈추는 지점
  현재: phase [기본값]
  선택지: phase / req / merge
  ⚠️ HIGH 위험 티켓은 ...
  Enter=유지
> merge
```

## 요구사항

### R1 — enum 질문은 방향키로 고른다
값이 정해진 질문(추론강도 6개 · stopGate 3개)은 ↑/↓로 이동하고 Enter로 확정한다.
사용자가 값을 정확히 타이핑해야 하는 부담과 오타를 없앤다.

🔴 **자유 입력 질문은 그대로 둔다.** 리뷰 모델은 enum이 아니다(codex가 받는 모든 모델 문자열).
선택지를 만들 수 없으므로 지금의 자유 입력이 맞다.

### R2 — setup 시작 시 배너
텍스트 그래픽으로 도구 이름과 버전을 보여 준다. 첫인상이자 "지금 무엇을 실행 중인지"의 표시다.

### R3 — 종료 시 `req.config.json` 커밋 안내
실측(matjib-nuxt): 진행 중 티켓이 있는 저장소에서 setup을 실행하면 `req.config.json`이
uncommitted 상태가 되어 **`req:doctor`가 D10/D13 FAIL**을 낸다(커밋하면 즉시 PASS).
지금 setup은 저장 사실만 알리고 이 다음 동작을 안내하지 않는다.

## 제약

- **외부 의존성을 추가하지 않는다**(사용자 결정). CommitGate는 소비자 프로젝트의 devDependency이고
  설치 표면이 곧 비용이다. 필요한 위젯은 "단일 선택 리스트" 하나뿐이라 라이브러리를 들일 이유가 없다.
- **비-TTY 거부 계약은 그대로다**(REQ-2026-060). 방향키 도입이 이 계약을 완화하지 않는다.
- **기존 `Prompter` 주입 seam을 유지한다.** 지금 setup 테스트는 문자열을 주입해 완전히 결정적인데,
  그 seam이 깨지면 setup 전체의 회귀 검증이 사람 눈에만 의존하게 된다.
- 저장 계약 무회귀: **건드린 키만 쓴다** · Enter=유지=미기록 · 원자적 저장 · 로그인 실패 시 미저장.

## 비목표

- 다중 선택·검색·자동완성 — 필요한 질문이 없다.
- 자유 입력 질문의 선택지화 — R1의 명시 제외.
- 전체 TUI 프레임워크 도입.
- 다른 verb(`check`·`delivery` 등)의 UI 변경 — setup만 대화형이다.

## 수용 기준

1. enum 질문에서 ↑/↓로 커서가 움직이고 Enter로 확정된다. 확정값이 지금과 **같은 경로**로 검증·저장된다.
2. 자유 입력 질문(리뷰 모델)은 동작이 바뀌지 않는다.
3. 비-TTY에서 setup은 여전히 거부된다(메시지 동일).
4. 기존 setup 유닛 테스트가 **수정 없이** 통과한다(주입 seam 보존 증명).
5. 키 처리 로직이 순수 함수로 분리되어 키 시퀀스 → 결과가 테스트로 고정된다
   (↑/↓ 경계 순환 · Enter 확정 · Ctrl+C 중단 · **분할 도착한 escape sequence**).
   🔴 취소 키는 Ctrl+C 하나다 — 단독 Esc는 시퀀스 시작과 구별할 수 없어 취소로 쓰지 않는다.
6. 배너가 setup 시작 시 1회 출력되고, 비-TTY 거부 경로에서는 출력되지 않는다.
7. 저장 후 출력에 `req.config.json` 커밋 안내가 포함된다.
8. `Prompter`가 raw mode를 **모든 종료 경로에서 해제**한다(정상 종료·예외·Ctrl+C).
   해제하지 못하면 사용자 터미널이 에코 없는 상태로 남는다.
