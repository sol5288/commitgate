# REQ-2026-083 요구사항

## 무엇을

**codex가 없거나 setup이 안 끝난 상태를 말하는 런타임 표면 전부**가, 사용자가 그 자리에서 실행할 수 있는
**다음 명령**을 함께 주도록 고친다.

## 왜 — 실측 근거

### ① 🔴 `npx commitgate init`의 설치 후 안내가 `setup`을 **0회** 언급한다

0.12.1 배포본을 격리 환경(빈 폴더 · 별도 npm 캐시)에 실설치해 확인했다. `installGuidance`가 내는 순서:

```
3. codex --version → 4. req.config.json 확인 → 5. node_modules gitignore
→ 6. 설치분만 stage → 7. 무관한 변경 정리 → 8. npm run req:new -- <slug> --run
```

🔴 **안내대로 따르면 8번에서 막힌다** — setup 미완료면 `req:new`가 차단되기 때문이다(REQ-2026-062).
REQ-2026-082가 `--help`에서 고친 것과 **같은 결함**인데, 그때 범위를 `--help`로만 잡아 놓쳤다.
오히려 이쪽이 더 나쁘다: `--help`는 일부만 치지만 **init 출력은 설치하는 사람 전원이 본다.**

### ② 🔴 codex 미설치를 말하는 표면들이 **설치 명령을 주지 않는다**

`runSetup`에 probe를 주입해 신규 PC 상태를 재현했다(실제 codex는 건드리지 않음).

| 상태 | 사용자가 보는 것 | 판정 |
|---|---|---|
| **A. codex 미설치** | `codex CLI 를 실행할 수 없습니다(spawn codex ENOENT). 설치·PATH 를 확인한 뒤 다시 실행하세요 — 설정을 저장하지 않았습니다.` | 🔴 **설치 명령이 없다.** 신규 PC에서 막다른 길 |
| **B. 미로그인** | `codex 로그인이 필요합니다 — 브라우저 인증을 마치면 이어집니다.` → `codex login` **실제 호출**(1회) → 재검증 → 실패 시 `터미널에서 codex login 을 마친 뒤 …` | ✅ **정상 동작.** 이 경로는 고칠 것이 없다 |

같은 결함이 다른 표면에도 있다:

- `bin/check.ts` C2: `리뷰어 CLI(codex)를 실행할 수 없습니다(…). 설치·PATH 를 확인하세요` — 명령 없음
- `bin/init.ts` `installGuidance` 3번: `codex --version   # 리뷰 실호출 전제` — 없을 때 뭘 할지 없음

🔴 저장소 전체에서 `npm i -g @openai/codex`를 **런타임에 말하는 곳은 단 한 곳**이다 —
REQ-2026-082가 0.12.1에서 추가한 `--help`(`bin/init.ts:1491`). 나머지는 전부 문서(`docs/quick-start*`)에만 있고,
**막힌 사용자는 문서가 아니라 터미널을 보고 있다.**

## 제약

- 🔴 **B(미로그인) 경로는 건드리지 않는다.** 실측으로 정상 동작을 확인했다 — 고칠 것이 없는 곳을 만지지 않는다.
- 🔴 **게이트 동작·보장 계약 불변.** 이 REQ는 **메시지와 안내 순서**만 바꾼다. 판정 로직·차단 조건은 그대로다.
- `check`는 읽기 전용이며 어떤 게이트에도 배선되지 않는다 — 그 성질을 유지한다.
- 설치 명령은 **한 가지 표기로 통일**한다(현재 `npm i -g @openai/codex`와 `npm install -g @openai/codex`가 섞여 있다).

## 완료 기준

- `installGuidance`가 `setup`을 **`req:new`보다 먼저** 안내한다.
- codex 미설치를 말하는 **모든 런타임 표면**이 설치 명령을 함께 준다.
- 위 두 불변식을 **회귀 가드**로 고정한다 — 변이 검사로 실제로 잡는 것까지 확인한다.
- `npm test` · `npm run typecheck` · `npm run docs:lint` 그린.
