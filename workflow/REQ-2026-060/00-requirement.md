# REQ-2026-060 요구사항

commitgate setup — 대화형 기반

## 배경

설치 직후 사용자는 `req.config.json`을 **손으로 열어** 리뷰 모델·추론강도를 설정해야 한다.
그리고 리뷰어 CLI(`codex`)의 설치·로그인 여부를 확인하는 수단이 코드에 **전혀 없다**
(`codex --version`/`codex login status` 호출부 0건). 그래서 미로그인은 첫 리뷰 호출에서야
`codex 종료 코드 1`이라는 불투명한 형태로 드러나고, 그 시도는 `ReviewCallError('dispatched')`로
분류되어 **리뷰 예산까지 차감한다**(`adapters.ts:190-192`).

## 요구사항

| # | 내용 |
|---|---|
| **R1** | `commitgate setup` verb 신설 — **대화형 전용**. 비대화형(`--set` 등) 경로를 만들지 않는다 |
| **R2** | setup에서 **리뷰 모델·추론강도(effort)** 를 선택한다 |
| **R3** | 모델 설정 후 **CLI 로그인 과정**을 거친다 — setup이 `codex login`을 직접 실행하고 결과를 재검증한다 |
| **R4** | 설정 저장은 **원자적**이어야 하고, 중단 후 재실행으로 복구된다 |
| **R5** | 사용자용 문서와 에이전트 계약을 갱신한다 |

### R1이 대화형 전용인 이유

`req-commit.ts:111`이 이미 같은 원칙을 말한다 — *"가장 강한 보장 = 사용자가 직접 실행"*.
대화형 전용으로 두면 **에이전트가 게이트 정책을 스스로 바꾸는 경로가 구조적으로 닫힌다.**
이 저장소의 모든 기존 명령은 flag 기반이고 에이전트가 비대화형으로 실행하는 것이 설계 전제였으므로
(`readline`/`isTTY`/`process.stdin` 사용처 0건), `setup`은 **최초의 대화형 명령이자 최초의 사람 전용 명령**이다.

## 🔴 비목표 (이 REQ에서 하지 않는 것)

리뷰어가 "setup이 아무것도 강제하지 않는다"를 결함으로 읽지 않도록 **명시한다.**
아래는 누락이 아니라 **범위 결정**이며, 각각 별도 REQ로 예정돼 있다.

| 비목표 | 예정 REQ | 이 REQ에서의 상태 |
|---|---|---|
| **setup 완료 강제**(마커 + 워크플로 verb 공통 preflight + doctor 진단) | B | setup은 아무것도 강제하지 않는다. 마커도 쓰지 않는다 |
| **멈춤 게이트 `stopGate` 선택** | B2 | setup은 `phaseCommit`/`stopGate`를 묻지 않는다 |
| **delivery set**(여러 REQ 묶음 → main 병합 전 정지) | B3 | 전혀 다루지 않는다 |
| **`commitgate check`** — 비대화형 진단 verb | A2 | 🔴 **에이전트가 호출할 진단 표면을 만들지 않는다.** 로그인 재검증은 setup **내부 함수로만** 존재한다 |
| **reviewer provider 교체**(cursor 등) | C | **Codex 전용**. provider를 묻지 않는다 — 아직 선택지가 없는 것을 묻는 것은 거짓 UI다 |
| **리뷰 원장에 모델·effort·provider 기록** | E | 아래 제약 참조 |
| **리뷰 호출 auth preflight** | F | setup 밖에서는 로그인을 검사하지 않는다 |

## 제약 — 릴리스 단위

🔴 **이 REQ는 단독 배포하지 않는다. 원장 감사 REQ(E)와 같은 릴리스로 낸다.**

현재 커밋되는 감사 기록(`review-ledger.jsonl`)에는 **어떤 모델이 리뷰했는지가 없다**
(`review-ledger.ts:83-96`의 `LEDGER_KEYS`에 부재). 모델은 gitignore된 측정 전용 로그
(`.review-calls.jsonl`)에만 있다. 이 REQ는 모델 교체를 **쉽게** 만들므로, E보다 먼저 릴리스되면
"모델은 자유롭게 바꾸는데 커밋된 이력은 그 사실을 모르는" 창이 배포본 사이에 열린다.

*(이 갭 자체를 이 REQ가 만드는 것은 아니다 — 지금도 손으로 파일을 고치면 같다. 다만 이 REQ가
그 경로를 상용화하므로 릴리스를 묶는다. **E의 구현은 이 REQ의 범위가 아니다.**)*

## 수용 기준

1. TTY가 아닌 환경에서 `commitgate setup`은 **질문을 하나도 던지지 않고** 즉시 실패한다(blocking read 없음).
2. TTY 환경에서 모델·effort를 선택하면 `req.config.json`에 반영되고, **다른 키는 보존**된다.
3. 미로그인 상태에서 setup이 `codex login`을 실행하고, 완료 후 재검증에 성공해야만 설정이 저장된다.
4. 로그인 취소·실패 시 **`req.config.json`이 변경되지 않는다**.
5. 재실행 시 **현재 값이 기본 답변으로 제시**되고 Enter로 유지된다.
6. `AGENTS.md`에 "사람 전용 명령" 절이 있고, 에이전트가 setup을 실행하지 않도록 지시한다.
7. `npm test` green · `tsc --noEmit` 0.
