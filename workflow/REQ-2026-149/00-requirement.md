# REQ-2026-149 요구사항

> **REQ-2026-148 의 대체 REQ.** 그 티켓은 설계 8라운드로 예산이 소진됐다. 매 라운드 실제 결함이
> 나왔고 **r02~r05 의 P1 이 전부 DEC-3(checkpoint 귀속) 하나**에서 나왔다 — 그래서 DEC-3 은
> **분리**했고(아래 참조), r07 의 마지막 P1(`req:confirm --method`)까지 반영을 마친 **완성된 설계**를
> 이 티켓이 그대로 이어받는다.
>
> 🔴 **이 문서의 P1 대응은 재검토 대상이 아니라 전제다.** REQ-2026-148 의 8라운드가 이미 값을 치렀다.

## 무엇을

도구가 안내한 명령이 **현재 상태에서 실행 가능하면서도, 티켓 밖 변경·사람 통제점·정확한 대상 귀속을
우회하지 않게** 한다. 외부 리뷰가 지적한 5건을 고친다.

## 왜 — 5건 전부 실측 재검증됨

| # | 결함 | 실측 |
|---|---|---|
| 1 | **보고의 예시 명령만 실행해도 사람 결정 없이 replace 가 커밋된다** | `nonconvergence.ts` 가 `--confirm "승인 문장"` 을 **실행 가능한 값**으로 내고, `req-review-exception` 은 trim 비어 있음만 본다 |
| 2 | **파킹 안내가 티켓 밖 staged 파일까지 커밋한다** | `git add -- "<티켓>"` 다음 줄이 **pathspec 없는** `git commit` 이다 — 이미 staged 인 것이 전부 실린다 |
| 3 | **checkpoint 복구가 "이 소비의 증거"를 확인하지 않는다** | `evidence-recovery.ts:226` 은 `headManifest.trim()` **비어 있지 않음**만 본다. 과거 무관한 승인 행으로도 D10 예외가 열린다 |
| 4 | **위임 명령이 cmd.exe 에서 안전하지 않다** | `shellSafeArg` 는 `"` `` ` `` `$` `\` 만 막는다. cmd.exe 는 **큰따옴표 안에서도 `%VAR%` 를 확장**한다 |
| 5 | **`--series` 로 지정한 것과 실제로 닫는 series 가 다를 수 있다** | `closeSeriesHumanResolution` 은 `(kind, phase)` 의 **첫 열린 record** 를 닫는다 |

🔴 **리포트 1건은 정정한다.** `^` 는 git 이 ref 로 **거부**한다(`git check-ref-format` 실측) — 도달 불가
문자다. 실제로 유효하면서 위험한 것은 **`%` 와 `!`** 다.

```
feat/req-2026-146-%PATH%   유효
feat/req-2026-146-!VAR!    유효
feat/req-2026-146-^X       무효
```

## 이 REQ 의 성격

🔴 **전부 이 세션이 방금 만든 결함이다.** REQ-142·145·146·147 이 "안내는 하는데 실행 불가"를 고치면서
그 반대편 — **안내가 너무 잘 실행돼서 통제점을 넘는다** — 을 만들었다. 실행 가능성과 안전성은
같은 축의 양끝이고, 한쪽만 보면 다른 쪽이 무너진다.

## 제약

- 🔴 **"사람인지 기술적으로 증명한다"고 주장하지 않는다.** 이번 범위는 **도구가 스스로 만든 범용
  승인값을 도구가 되받지 않는 것**뿐이다.

  🔴 **한계를 정확히 적는다**(설계 r03 P1 — 초안이 "손으로 타이핑하면 통과한다"고 써서 설계와
  자기모순이었다). 실제 한계는 이것이다: **예약 문자열은 누가 넣든 거부되고**, 예약이 아닌 문자열은
  그것이 무의미해도(`"x"`·`"asdf"`) 여전히 통과한다. 즉 이 REQ 는 **도구가 자기 출력을 되받는 고리**만
  끊고, 값의 **진정성**은 판정하지 않는다.

  예약 문자열은 `"승인 문장"`·`"왜 대체하는가"` 처럼 **도구가 만든 범용 라벨**이라, 실제 사람의 결정
  기록이 정확히 그 값일 이유가 없다. 무조건 거부해도 정상 사용을 막지 않는다.
- 🔴 **정상 crash window 복구는 여전히 `--finalize --run` 한 번으로 수렴**해야 한다(#3 을 조이면서
  REQ-2026-142 가 연 정상 경로를 막으면 안 된다).
- 🔴 phase id 에 `#` 이 든 원문 대조 계약(REQ-2026-145)은 **유지**한다.
- 안전하게 렌더링할 수 없으면 **명령을 만들지 않고** 데이터로 보여 준다(기존 계약 확장).

## 완료 기준

1. 보고 원문 명령을 그대로 실행하면 **실패**하고, 실제 사유·승인 문장이면 성공한다.
2. 티켓 밖 staged 파일이 파킹 커밋에 **들어가지 않고** staged 로 남는다.
3. ~~checkpoint 귀속~~ → 🔴 **후속 REQ 로 분리**(설계 DEC-3). 설계 리뷰 7라운드의 P1 이 전부 이
   하나에서 나왔고, 나머지 네 건은 r02 이후 P1 이 없었다 — 묶여 있어서 같이 못 나간다.
   **결함 3 은 이 REQ 이후에도 남아 있다.**
4. `%`·`!` 가 든 유효 branch 에서 `req:next` 가 **실행 불가능한 명령을 내지 않는다**.
5. 같은 `(kind, phase)` 에 열린 series 가 둘일 때 `--series` 로 **지정한 것만** 닫힌다.
