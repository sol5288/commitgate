# REQ-2026-112 요구사항

옛 HIGH 백스톱 서술 정정 + 가드 범위 확장 + 소비자 알림 검사

## 무엇을 / 왜

REQ-2026-071이 *"HIGH 위험 티켓은 어떤 설정에서도 매 phase 사람 확인"* 이라는 백스톱을 **의도적으로
제거**하고, 정지 지점을 `stopGate`가 단독으로 정하도록 바꿨다.
REQ-2026-073이 그때 뒤처진 문서 5곳을 정정하고 회귀 가드를 만들었다.

**그런데 그 정정이 `README` + `docs/`에만 적용됐고, 같은 주장이 6곳에 그대로 살아 있다.**

| # | 위치 | 성격 |
|---|---|---|
| 1 | `bin/setup.ts:230` (`STOP_GATE_HIGH_NOTICE`) | 🔴 **setup 마법사가 사용자에게 보여주는 고지** |
| 2 | `AGENTS.template.md:77` | `init`이 소비자 `AGENTS.md`로 복사하는 계약 템플릿 |
| 3 | `docs/ssot-design/04-user-roles-and-permissions.md:54` | 설계 SSOT — **가드 범위 안인데 통과했다** |
| 4~6 | `scripts/req/lib/config.ts` 39·53·214 | 코드 주석 |

### ①이 가장 나쁘다

그 문장은 사용자가 `stopGate` 값을 **고르는 순간** 화면에 뜬다(`hintFor`가 질문마다 붙인다).
바로 위 주석이 존재 이유를 *"`req`를 고른 사용자가 '이제 전부 자동'이라고 오해하지 않게"* 라고 적어 두었는데,
**현실은 정반대다** — `stopGate: 'req'`(기본값)에서 HIGH 티켓의 중간 phase는 멈추지 않는다
(`req-commit.ts:133`). 문장도 거짓이고 그 문장을 정당화한 근거도 뒤집혀 있다.

### ③은 가드가 **자기 범위 안에서** 놓쳤다

`docs/ssot-design/04:54`는 `docs/**` 재귀 검사 대상인데 통과했다. 표현이 다르기 때문이다 —
등재된 것은 `정책과 무관하게 매 phase 확인`인데 실제 문장은 `정책과 무관하게 유지`다.
`docs-stale-claims.test.ts`가 스스로 적어 둔 한계가 그대로 실현됐다.

> **범위를 넓히는 것만으로는 부족하다.** 같은 주장의 **표현 변형**이 이미 범위 안에 살아 있다.

### 기설치 소비자는 자동으로 못 고친다

- `bin/init.ts:1234` — `AGENTS.md`는 **부재 시에만** 복사한다(계약 보존).
- `commitgate sync`는 persona·스키마·gitignore 축만 다룬다. `AGENTS.md`를 건드리지 않는다.
- D21(Quick Start 드리프트)은 `<!-- commitgate:quickstart -->` 블록만 본다. 문제의 77행은 그 **밖**이다.

→ 갱신 경로가 없으므로 **진단으로 알린다**(사용자 결정: 방안 b — 계약 파일을 도구가 고치지 않는다).

## 제약

1. 🔴 **정정문에 옛 문구를 축자 인용하지 않는다.** 가드는 부분 문자열 검사라 인용도 실패시킨다.
   폐기된 표현을 설명할 때는 **풀어 쓴다**.
2. 🔴 **소비자의 `AGENTS.md`를 도구가 수정하지 않는다.** 사용자 소유 파일이다. 알리기만 한다.
3. 가드를 **일반 문서 스캐너로 키우지 않는다** — REQ-2026-044가 오라클을 명세하지 못해 폐기한 길이다.
   판정은 기계적이고, 실패하면 무엇을 고칠지 명확해야 한다.
4. `stopGate`의 **동작을 바꾸지 않는다.** 이 REQ는 서술과 진단만 다룬다.
5. 새 진단은 **WARN이다.** 소비자의 진행을 막지 않는다.

## 완료 기준

| # | 기준 | 검증 |
|---|---|---|
| AC-1 | 6곳의 서술이 실제 동작과 일치한다 | 아래 AC-1a·AC-1b로 **전 지점을 기계 검사**한다 |
| **AC-1a** | **배포 지침 표면**(`AGENTS.template.md`·`templates/**`·`skills/**`·`review-persona.md`)에 폐기 문구가 없다 | 파일 내용 검사 |
| **AC-1b** | **코드 표면**(`bin/setup.ts`·`scripts/req/lib/config.ts`)에 폐기 문구가 없다 | 같은 방식. 대상은 **명시적 파일 목록**이며 등재 모듈·가드 자신은 제외 |
| AC-2 | `STOP_GATE_HIGH_NOTICE`가 정지 지점을 `stopGate`가 정한다고 말한다 | **상수를 import해 값 검증**(AC-1b 위에 얹는 더 강한 오라클) |
| AC-3 | 가드의 검사 대상 목록에 위 표면들이 실제로 들어 있다 | 대상 목록 단언 + **변이 검사** |
| AC-4 | 표현 변형(`정책과 무관하게 유지`)이 등재돼 재발을 잡는다 | 변이 검사 |
| AC-5 | 소비자 `AGENTS.md`에 폐기된 주장이 있으면 **새 진단이 WARN**한다 | hermetic repo에서 `main()` 실행 |
| AC-6 | 그 진단이 없는 정상 설치본에서는 조용하다(오탐 없음) | 대조군 |
| **AC-7a** | 진단이 쓰는 매칭 함수가 정본과 **같은 객체**다 | `toBe` 참조 동일성 — 내용이 같은 **사본 구현도 실패**한다 |
| **AC-7b** | 진단이 정본 목록 **전체**를 인식한다 | 모든 항목을 각각 `AGENTS.md`에 넣고 `main()`으로 D29 발화 확인 |

> 🔴 **AC-1이 AC-1a·AC-1b로 갈라진 이유**(설계 리뷰 r01 P1): 원안은 배포 문서와 상수만 검사해서,
> `config.ts`의 주석 3곳과 `setup.ts`의 근거 주석을 **옛 주장 그대로 남겨도 전 검증이 통과**했다.
> 6곳 정정을 요구하면서 4곳을 검사하지 않는 오라클이었다.

> 🔴 **AC-7이 두 겹으로 갈라진 이유**(설계 리뷰 r01·r02 P1 연속):
> - r01: "같은 모듈을 import하는가"만 보면 **동일한 배열 사본**을 들고 있어도 통과한다.
> - r02: 전수 발화 검사로 바꿨더니 이번엔 **사본이 정본보다 적을 때만** 잡혔다. 내용이 같은 사본은 그대로 통과.
>
> 그래서 **구조 + 참조 + 행동** 세 겹으로 간다. 구조: `req-doctor`가 목록을 import하지 않고
> **매칭 함수만** 가져가 사본을 둘 자리를 없앤다. 참조(AC-7a): 그 함수가 정본과 같은 객체인지 `toBe`로 본다.
> 행동(AC-7b): `main()`을 통해 전 항목이 발화하는지 본다. 자세한 근거와 **남는 한계**는 설계 DEC-4.
