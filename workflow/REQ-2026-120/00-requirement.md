# REQ-2026-120 요구사항

리뷰 전송 보안·프롬프트 비용 — secret scan(fail-closed)·크기 표면

## 배경 (무엇이 문제인가)

`req:review-codex`는 조립 프롬프트(staged diff 전문 또는 설계 문서 전문 + persona)를 stdin으로
Codex(OpenAI)에 전송한다. 계약(guarantees·AGENTS §6)은 "마스킹·스크러빙·길이 상한이 **없다**"고
정직하게 밝히고 확인을 Builder의 의무로 두지만, 도구가 보강할 수 있는 부분이 있다:

1. **비밀 유출은 비가역이다.** staged에 실수로 섞인 개인키·API 토큰이 프롬프트에 실리면 외부
   전송을 되돌릴 수 없다. 현재 어떤 검사도 전송 전에 서지 않는다.
2. **크기의 표면이 없다.** 소비자 실측에서 단일 프롬프트 ~721KB가 관측됐다. `prompt_bytes`는
   로그에만 남고(REQ-2026-045), 실행 시점에 사용자가 크기를 알 방법이 없다 — 비용은 조용히 나간다.

untracked 파일의 의도치 않은 포함은 **이미 구조적으로 막혀 있다**: D10이 리뷰 시점 워킹트리
clean을 강제하므로 staged 밖 파일이 diff에 들어올 경로가 없다(이 REQ는 그 사실을 확인만 한다).

## 요구

- **R1 · staged secret scan (전송 전·fail-closed)** — 조립 프롬프트 전체를 **고신뢰 결정적
  패턴**(개인키 PEM 헤더·AWS Access Key·GitHub 토큰·Slack 토큰·Google API 키·OpenAI 키·JWT)으로
  스캔한다. 일치하면 **Codex를 호출하지 않고** 명확히 실패한다. 실패 메시지는 패턴명과
  **마스킹된 매치**(앞 일부만)를 보여준다 — 비밀 값을 화면에 다시 찍지 않는다.
- **R2 · 정책 config** — `secretScan: 'block' | 'warn' | 'off'`, 기본 **`block`**.
  warn-first 선례(0.13.1)는 수렴 마찰 맥락이었고, 이것은 **비가역 유출 방지**이며 패턴이
  고신뢰(오탐 근접 0)라 기본 차단이 비례적이다. `warn`(경고 후 전송)·`off`가 탈출구다.
- **R3 · 예산 보호** — 차단은 리뷰 예산을 소모하지 않는다: 스캔은 원장 `attempt-opened` 기록
  **전에** 실행된다(예산 차감 전 차단).
- **R4 · 프롬프트 크기 표면** — `promptWarnBytes`(기본 256KiB): 초과 시 구성 분해(persona/문서/
  diff 바이트)와 함께 경고하고 **전송은 진행**한다. `promptMaxBytes`(기본 null=무제한, opt-in):
  설정 시 초과하면 fail-closed로 중단하고 분할·lockfile 요약 등 축소 경로를 안내한다.
  **어느 경우에도 조용한 절단은 없다.**
- **R5 · 문서 정합** — guarantees(한/영)의 "마스킹·스크러빙·길이 상한 없음" 서술을 실제 동작
  (기본 secret scan 차단·opt-in 상한)에 맞게 갱신한다.

## 제약

- 고신뢰 패턴만 쓴다 — 엔트로피 기반·일반 휴리스틱(`password=` 류)은 오탐이 경고 피로를 만들므로
  제외한다(확장은 데이터 후).
- diff·문서 본문을 **재작성·마스킹해서 전송하지 않는다** — 리뷰 입력의 무결성(승인 바인딩)이
  깨진다. 검사는 전송 여부만 정한다.
- codex의 `--sandbox read-only` 저장소 읽기 노출은 이 REQ의 범위 밖이다(프롬프트 스캔으로 막을 수
  없음 — 계약 문서화 유지).
- 네트워크·추가 유료 호출 없음. 테스트는 fake 어댑터(기존 관례).

## 완료 기준

1. PEM 개인키·AKIA 키 등 각 패턴이 staged diff에 있으면 기본 설정에서 리뷰가 **Codex 호출 없이**
   실패하고, 메시지에 패턴명 + 마스킹된 매치가 나온다(원문 전체 재출력 없음).
2. 차단된 시도는 원장에 `attempt-opened`가 남지 않는다(예산 미차감).
3. `secretScan: 'warn'`이면 경고 후 전송이 진행되고, `'off'`면 스캔하지 않는다.
4. 일반 코드·40자 SHA·UUID·해시 값은 오탐하지 않는다.
5. 프롬프트가 `promptWarnBytes` 초과면 구성 분해와 함께 경고가 나오고 전송은 진행된다.
6. `promptMaxBytes` 설정·초과 시 fail-closed로 중단되고 축소 안내가 나온다(절단 없음).
7. guarantees 한/영이 새 동작을 정확히 서술한다(docs 가드 그린).
