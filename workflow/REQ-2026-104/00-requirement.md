# REQ-2026-104 요구사항

문서 진실성 가드 범위 확장 + 낡은 고아 문서 제거

## 배경

2026-08-02 자체 감사의 문서 축 후속(A트랙 2번째). REQ-2026-103 구현 중 **실제 사례가 하나 나왔다**: `docs/ssot-design/06`과 `gaps-and-decisions.md` G-06이 도달 불가였던 resume 코드를 "향후 opt-in용으로 보존"이라 서술해, 없는 준비 상태를 있는 것처럼 읽히게 하고 있었다. REQ-2026-073과 같은 종류의 결함이다.

감사가 지목한 문서 항목을 실측으로 재검증한 결과는 다음과 같다.

| 감사 주장 | 실측 결과 |
|---|---|
| `docs/ssot-design/`(18파일·285KB)에 `docs-stale-claims` 가드가 없다 | **사실.** `tests/unit/docs-stale-claims.test.ts:86`이 `readdirSync(join(root,'docs'))`로 **최상위만** 훑는다(비재귀) |
| `codex-review-request*.md`(68KB)가 참조 0건이고 내용이 낡았다 | **분류 오류(감사가 틀렸다).** 참조 0건·내용 낡음은 사실이지만, 이 파일들은 **`.gitignore:19`에 등재된 일회용 스크래치**다 — 주석이 "Codex 리뷰 요청서(일회용 핸드오프, **커밋 대상 아님**)"라고 명시한다. 문서 부채가 아니라 설계상 버리는 산출물이고, git이 추적한 적도 없다 → **범위 밖**(아래 경위) |
| Quick Start가 3중 서술이고 `check` 명령 유무로 이미 drift 중이다 | **과장.** README는 랜딩(3단계), `docs/quick-start.md`는 상세판이고 `check`는 "언제든 확인할 수 있습니다(비대화형·읽기 전용)"로 **선택 조회**임이 명시돼 있다. 의도된 계층이지 불일치가 아니다 → **범위 밖** |
| `CHANGELOG.md`(139KB)가 tarball의 11.8%다 | 사실이나 **가치 낮음** → 범위 밖(아래) |

## 요구

1. **`docs-stale-claims`의 검사 대상을 `docs/` 하위 전체로 넓힌다**(재귀). 현재 무가드인 `docs/ssot-design/` 18파일이 포함된다.
   - 🔴 **효과를 과장하지 않는다**: 이 가드는 **과거에 실제로 저지른 문장 12개를 고정 문자열로** 막는 장치다. 현재 ssot-design에는 그 12개가 **0건**이므로 확장은 즉시 통과하며, **REQ-103이 발견한 resume 서술도 이 확장으로는 잡히지 않았을 것이다**(목록에 없는 새 문장이었다). 얻는 것은 "이미 아는 거짓말이 무가드 구역으로 이주하지 못한다"는 예방뿐이다.

2. **REQ-2026-103이 만든 거짓 서술을 금지 목록에 등재한다.** 이 목록의 규칙은 "한 번 저지른 문장은 다시 못 들어온다"이며, resume 서술이 정확히 그 사례다.

## 비요구(명시적 범위 밖)

- 🔴 **`codex-review-request*.md` 삭제 — 착수했다가 전제가 반증되어 철회한다.**
  초안 요구는 이 두 파일(68KB)을 "낡은 고아 문서"로 보고 삭제하는 것이었다. 구현 중 확인해 보니 **`.gitignore`가 이미 이들을 일회용 핸드오프 스크래치로 규정**하고 있었다(19행 + 주석). git이 추적한 적이 없으므로 삭제는 **저장소에 아무 diff도 만들지 않는다** — REQ로 다룰 변경 자체가 성립하지 않는다.
  **경위(정직하게)**: 이 사실을 확인하기 **전에** 워킹트리에서 `rm`으로 지웠다. untracked였으므로 되돌릴 수 없다. 설계상 버리는 산출물이라 실질 손실은 없다고 판단하지만, **추적 상태를 확인하기 전에 지운 것은 절차 위반이다**. 재발 방지: 삭제 대상은 `git ls-files`로 추적 여부를 먼저 확인한다.

- **Quick Start 통합**: 위 표대로 실제 불일치가 없다. 손대면 오히려 README 랜딩의 간결함을 해친다.
- **`CHANGELOG.md`를 `files[]`에서 제외**: tarball 50KB(gzip) 절감은 devDependency CLI에서 체감되지 않는 반면, 소비자는 오프라인 변경 이력을 잃는다. 대부분의 npm 패키지가 CHANGELOG를 동봉하는 관행과도 어긋난다. **바이트 절감은 이 프로젝트의 문제가 아니다** — 비대함의 실체는 유지보수 면적이었다.
- **`req.config.json.sample`을 `files[]`에서 제외**: 런타임이 읽지 않는 것은 맞지만 **예시 문서**로서 값을 하고(`tests/unit/req-config.test.ts`가 유효성을 지킨다) 544B다. 감사의 "dead payload" 분류는 과했다.
- **`package.json` scripts 4개(`test`·`smoke`·`typecheck`·`docs:lint`)가 배포본에 없는 파일을 가리키는 문제**: 소비자가 부를 이유가 없어 실해가 없다. 별도 판단.

## 완료 기준

- `npm test`(docs-stale-claims 포함) 그린 · `npm run docs:lint` 통과.
- 확장된 가드가 실제로 `docs/ssot-design/` 파일을 검사 대상에 포함함을 테스트가 단언한다(범위 회귀 방지).
- 소비자 영향 0: `docs/`는 `package.json` `files[]`에 없어 애초에 배포되지 않는다.
