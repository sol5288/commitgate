# REQ-2026-071 요구사항 — 멈춤 지점은 `stopGate`만이 정한다

## 배경 (사용자 지시)

> "기본값 완화의 파급에 대한 사항이다. **기존의 제약은 모두 제거되어야 한다.**
>  오로지 setup에서 지정한 기본 멈춤 지점의 설정에 따라 동작되도록 해야 한다."

지금은 `stopGate`와 **무관하게** 동작하는 정지가 하나 더 있다: **HIGH 위험 티켓의 매 phase 사람 확인**
(`userConfirmGate`). `stopGate: "req"`·`"merge"`를 골라도 HIGH 티켓은 phase마다 멈춘다.

## 요구사항

### R1 — 정지 횟수는 `stopGate`가 정한다
`phase`면 매 phase, `req`면 REQ 종료, `merge`면 묶음 종료. **HIGH라는 이유로 그 빈도가 바뀌지 않는다.**

### R2 — 🔴 사람 확인을 **없애는 것이 아니라 옮긴다** (사용자 확정 방안 (a))
HIGH 티켓에도 사람 확인은 **여전히 필요**하다. 다만 "매 phase"가 아니라 **`stopGate`가 정한 지점**에서
한 번 받는다.

🔴 그냥 지우면 REQ-2026-019가 폐기된 사유가 재발한다: HIGH는 매 phase **신선한** `user_commit_confirmed`
(사람 확인 + 실시각)를 요구하는데, 그 요구만 삭제하면 HIGH 변경이 **사람 확인 없이** 통합된다.

### R3 — 확인의 **의미**가 기록에 드러난다
`user_commit_confirmed`는 지금 "이 커밋을 사람이 승인했다"는 뜻이다. 확인 지점을 옮기면 그 의미가
"이 REQ를(또는 이 묶음을) 사람이 승인했다"로 바뀐다. **무엇을 승인한 것인지가 기록에서 읽혀야 한다.**

## 제약

- 🔴 **시각은 실제 시계.** 지어낸 타임스탬프는 REQ-2026-019 폐기 사유다.
- `risk_level`이 없거나 이상한 값이면 **자동 진행하지 않는다**(현행 fail-closed 유지).
- 통합(main 병합) 승인은 어느 값에서도 그대로 필요하다 — 이건 `stopGate`의 축이 아니다.
- 기존 설정(`stopGate: "phase"`)의 동작은 **바뀌지 않는다**.

## 비목표

- `stopGate` 값 추가·의미 변경.
- 통합 통제점(I1/I2/B1) 변경.
- `risk_level` 판정 방식 변경.

## 수용 기준

1. `stopGate: "phase"` + HIGH → 지금과 동일하게 매 phase 확인.
2. `stopGate: "req"` + HIGH → phase 커밋에서 멈추지 않고, **REQ 종료 시점에** 확인을 요구한다.
3. `stopGate: "merge"` + HIGH → 묶음 종료 시점에 확인을 요구한다.
4. 🔴 **완료된 HIGH REQ는 확인 없이 통합될 수 없다** — 확인이 없으면 `dev-complete`가 발행되지 않아
   종결도 `delivery integrate` 자격도 성립하지 않는다.
   ⚠️ 미완성 REQ를 손으로 push하는 것은 도구 밖이다(저장소 전반의 보증 범위 — 협력적 worker).
   이 REQ가 만든 구멍이 아니며, 미완성 REQ는 어느 `stopGate`에서도 통합 대상이 아니다.
4b. 🔴 요구되는 확인을 **기록할 도구 경로가 존재한다**(`req:confirm`) — 지금은 `state.json` 손편집뿐이다.
5. 🔴 `risk_level` 부재·오타·손상은 **자동 진행하지 않는다**(현행 유지).
6. 확인 기록에 **무엇을 승인한 것인지**(phase / REQ / 묶음)가 남는다.
7. 확인 시각은 실제 시계에서 읽는다.
