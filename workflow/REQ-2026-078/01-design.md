# REQ-2026-078 설계 — 그림이 반복을 보여 주고, 문장이 전제 지식을 요구하지 않게

> 정본 결정은 SSOT(해당 DEC). 본 문서는 그 결정을 랜딩에 어떻게 반영할지 기록.

## 현재 상태(변경 대상)

`README.md` / `README.en.md`의 **앞부분 두 절**(`## CommitGate란?` · `## 무엇을 보장하고…`).
REQ-2026-074에서 구조는 잡혔고, 이번은 **그림의 정확성**과 **문장의 난이도**다.

## 핵심 설계 결정

### DEC-1 — 🔴 그림은 **루프와 관문**을 그린다 (단선 흐름이 아니라)

지금 그림은 위에서 아래로 **한 번** 흐르고, 재검수는 오른쪽 주석 한 줄이다.
이 도구의 성격은 **"승인될 때까지 반복하고, 승인돼야 다음으로 간다"**이므로 그것이 형태여야 한다.

목표 형태(라벨은 구현에서 확정):

```
  요구사항
     │
     ▼
  ┌──── 반복 ────────────────────────┐
  │  ① 코드 쓰는 AI가 만든다          │
  │  ② 검사하는 AI가 본다             │
  │  고칠 점 있나? ── 있다 ──▶ ①로 ──┘
  │        │ 없다 = 승인
  ▼
  저장(커밋) — 승인받은 그 변경만
     │
     ▼
  남은 작업 있나? ── 있다 ──▶ ①로
     │ 없다
     ▼
  사람이 확인 (작업 완료 · 합치기)
```

🔴 **되돌아가는 화살표가 그림 안에 있어야 한다.** 주석으로 적으면 "반복한다"는 사실이
그림이 아니라 글에서 온다 — 그러면 그림을 넣은 이유가 없다.

### DEC-2 — 🔴 사람 확인 지점을 **기본값에 맞춘다**

현재 그림은 `req:commit` 옆에 "사람이 확인"을 붙여 **매 커밋마다 사람이 멈춘다**고 읽힌다.
기본값 `stopGate: "req"`에서는 **REQ 안의 커밋이 사람 정지 없이 진행**되고, 사람은
**REQ가 끝나는 지점**과 **합치기(통합)**에서 확인한다.

그림에서 사람은 **루프 밖·아래**에 둔다. 🔴 랜딩에 `stopGate` 세 값을 다시 설명하지 않는다 —
"사람이 멈추는 지점" 절이 이미 아래에 있고, **정본은 `docs/workflow.md`**다(REQ-2026-073 결정).

### DEC-3 — 🔴 안전 4문구는 **바꾸지 않고 풀이를 붙인다**

`tests/unit/readme-landing.test.ts`(D5-c)가 네 문장을 **바이트 단위로** 고정한다:

- `Codex 리뷰 승인 없이는 커밋되지 않습니다`
- `staged diff 전문을 외부(Codex·OpenAI)로 전송합니다`
- `git hook을 설치하지 않습니다`
- `애매하면 막습니다(fail-closed)`

수용기준 3(내부 용어 제거)과 수용기준 5(4문구 유지)가 여기서 부딪힌다.
**문장을 갈아치우는 대신 옆에 일상어 풀이를 붙인다.**

```
🔒 **Codex 리뷰 승인 없이는 커밋되지 않습니다.**
   검사하는 AI가 "괜찮다"고 하기 전에는 저장이 막힙니다.
```

왜: 그 네 문장은 **정확하기 때문에** 정본이다(무엇이 보장되는지 오해 없이 말한다).
쉽게 만든다고 정확성을 깎으면, 이 문서가 하는 유일한 약속이 흐려진다.
🔴 **정확한 문장 + 쉬운 풀이**가 답이지, 둘 중 하나를 고르는 문제가 아니다.

### DEC-4 — 나머지 내부 용어는 **역할 이름**으로 바꾼다

| 지금 | 바꿀 말 |
|---|---|
| `builder AI` / 개발 AI | **코드 쓰는 AI** |
| `Codex (Reviewer)` | **검사하는 AI** |
| `staged tree` | **이번에 저장할 변경분** |
| `git add` | (그림에서 뺀다 — 도구 내부 절차다) |
| `P1` | **고칠 점** |
| `stale` | **낡은 승인** |
| `AWAIT_HUMAN` | **사람이 확인하는 지점** |

🔴 `req:review-codex`·`req:commit` 같은 **명령 이름은 그림에서 뺀다.** 처음 읽는 사람에게
필요한 것은 "무슨 일이 일어나는가"이지 "어떤 명령이 그걸 하는가"가 아니다 —
명령은 아래 "자주 쓰는 명령" 표에 이미 있다.

### DEC-5 — 보안 경고는 **쉬워지되 약해지지 않는다**

두 경고는 위치(설치 안내 **앞**)와 강조(별도 블록)를 유지한다.
CLI 플래그(`--sandbox read-only`·`git diff --cached`)는 **괄호 안 부연**으로 내리고,
본문은 "무엇이 밖으로 나가는가"를 일상어로 말한다.

🔴 **약화 금지의 구체적 의미**: "전문(全文)이 나간다" · "diff에 없는 파일도 읽힐 수 있다" ·
"우회할 수 있다"는 사실이 문장에서 사라지면 안 된다. 쉬워지는 것은 **표현**이지 **내용**이 아니다.
