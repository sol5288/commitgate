# REQ-2026-078 요구사항 — 랜딩 앞부분을 비개발자도 읽히게, 현재 동작에 맞게

## 사용자 지시

> "readme 의 첫번째 부분이 우리 현재상태와 차이가 있는 것 같다. 그리고 쉽게 이해되지도 않는다.
> 비개발자 바이브코더들도 쉽게 이해되도록 현재 기준에 맞게 쉽게 다시 작성하면 좋겠다"
>
> "흐름도를 뭔가 코딩과 검수가 계속 반복되고 검수 승인이 되어야 다음 단계 진행되는 이런 과정이
> 한눈에 보여지도록 하면 좋겠다"

## 결함 ① — 흐름도가 현재 동작과 다르다 (부정확)

`README.md`의 흐름도가 `req:commit` 상자에 이렇게 붙어 있다:

```
    │    req:commit    │   ◀── 사람이 AWAIT_HUMAN 통제점에서 확인
    └──────────────────┘       (커밋 · 통합 · 릴리스)
```

→ **커밋할 때마다 사람이 확인**하는 것으로 읽힌다. 🔴 **기본값(`stopGate: "req"`)에서는 REQ 안의
phase 커밋이 사람 정지 없이 자동으로 진행되고**, 사람 확인은 **REQ를 완성시키는 커밋**과 **통합**에서만
요구된다. REQ-2026-071이 바꾼 동작인데 흐름도가 그 전 상태를 그리고 있다.

(REQ-2026-073이 문서 본문의 같은 종류 오류를 고쳤지만 **랜딩 흐름도는 대상이 아니었다.**)

## 결함 ② — 흐름도에 반복이 보이지 않는다

지금 그림은 위에서 아래로 한 번 흐르고, 재검수는 오른쪽 주석 한 줄로만 언급된다.
🔴 이 도구의 성격은 **"승인될 때까지 코딩↔검수를 반복하고, 승인돼야 다음으로 간다"**인데
그 반복과 관문이 그림에서 보이지 않는다.

## 결함 ③ — 첫 화면이 전제 지식을 요구한다

랜딩 앞부분(배지~보장 절)에 등장하는 용어:

| 용어 | 비개발자에게 |
|---|---|
| `staged tree` · `git add` · `git diff --cached` | git 스테이징 개념을 알아야 이해됨 |
| `P1` | CommitGate 내부 등급 |
| `stale` | 설명 없는 영어 전문용어 |
| `AWAIT_HUMAN` | 도구 내부 상태값 |
| `fail-closed` | 전문용어 |
| `REQ 워크플로` | 정의 없이 반복 등장 |
| `--sandbox read-only` | CLI 플래그가 경고문에 |

🔴 **"승인받은 바로 그 staged tree만 커밋된다"가 이 도구의 핵심 약속인데**, 그 한 문장을 이해하려면
git 스테이징을 알아야 한다. 대상 독자가 "AI에게 시켜서 코딩하는 사람"이라면 그 전제가 성립하지 않는다.

## 수용 기준

1. 흐름도가 **반복 루프**와 **승인 관문**을 한눈에 보여 준다 —
   "고칠 점이 있으면 되돌아가고, 승인돼야 다음으로 간다"가 그림만 봐도 읽힌다.
2. 흐름도의 사람 확인 지점이 **현재 기본값(`stopGate: "req"`)과 일치**한다.
   🔴 "매 커밋마다 사람이 확인한다"고 읽히지 않아야 한다.
3. 랜딩 앞부분에서 위 표의 내부 용어(`P1`·`stale`·`AWAIT_HUMAN`·`fail-closed`·`staged tree`·
   CLI 플래그)가 **설명 없이 등장하지 않는다**. 필요한 곳은 일상어로 바꾸거나 문서로 넘긴다.
4. 🔴 **보안 경고 2건(외부 전송·git hook 없음)은 약화되지 않는다.** 쉬운 말로 바꾸되
   **강조와 위치를 유지**한다 — 읽는 사람이 시작 전에 반드시 보게 한다.
5. 🔴 **기존 안전 4문구가 그대로 남는다.** `tests/unit/readme-landing.test.ts`(D5-c)가
   바이트 단위로 고정하고 있다 — 문장을 바꾸려면 그 테스트도 함께 고쳐야 하고,
   **불변식("설치 시작 헤딩보다 앞")은 유지**해야 한다.
6. 한/영 **양쪽**이 같은 구조. `docs:lint` green · `npm test` green.
