# REQ-2026-136 설계

> 정본 결정은 SSOT(해당 DEC). 본 문서는 그 결정을 현재 코드/구조에 어떻게 반영할지 기록.

## 현재 상태(변경 대상)

`bin/quickstart.ts`가 관리 블록 기계를 **이미** 갖고 있다:

- `QS_RE = /<!-- commitgate:quickstart -->[\s\S]*?<!-- \/commitgate:quickstart -->/` — 마커 쌍 매칭.
- `extractQuickstartBlock(templateBody)` — 템플릿에서 블록 추출.
- `injectQuickstart(...)` — dominant EOL 보존 · 첫 heading 뒤 삽입(펜스 인식) · 멱등 · 블록 밖 바이트 보존.
- verb: 기본 dry-run · `--apply` · 계약 마커 없는 `AGENTS.md`는 거부 · symlink escape 방지.
- `req:doctor` **D21**이 `quickstartBackfill`(insert/replace)로 부재·드리프트를 **구별해** WARN.

한계는 하나다: **블록이 하나로 하드코딩**돼 있다(`QS_RE`·함수명·D21 입력 모두 Quick Start 전용).
그래서 REQ-2026-131이 계약 본문에 넣은 자율 진행 절은 기존 파일에 닿을 길이 없다.

## 핵심 설계 결정

### DEC-1 — 관리 블록을 **집합**으로 선언한다

```ts
export interface ManagedBlock {
  /** 마커 id — `<!-- commitgate:<id> -->` … `<!-- /commitgate:<id> -->` */
  id: string
  /** 이 블록을 넣을 대상 파일(repo 상대). */
  targets: readonly string[]
}

export const MANAGED_BLOCKS: readonly ManagedBlock[] = [
  { id: 'quickstart', targets: ['CLAUDE.md', 'AGENTS.md'] },
  { id: 'autonomy',   targets: ['AGENTS.md'] },   // 계약 본문 — CLAUDE.md 에는 넣지 않는다
]
```

- 마커 정규식은 **id에서 생성**한다(`blockRe(id)`) — 상수를 블록마다 손으로 늘리지 않는다.
- `targets`가 파일별 대상을 선언하므로 "계약은 AGENTS.md만"이 **데이터로** 표현된다.

🔴 **`CLAUDE.md`에 계약 본문을 넣지 않는 이유**: 그 파일의 몫은 항상 로드되는 **자립형 Quick Start**다
(REQ-2026-039). 계약 전문을 거기 복제하면 두 벌이 갈라지고, 그 파일이 길어질수록 Quick Start의 존재
이유(첫 요청에서 올바른 첫 행동)가 희석된다.

### DEC-2 — 템플릿의 자율 진행 절을 마커로 감싼다

`AGENTS.template.md`의 `### 4-1. 자율 진행 — 언제 묻지 않는가` 절 전체를
`<!-- commitgate:autonomy -->` … `<!-- /commitgate:autonomy -->` 로 감싼다.

🔴 **본문은 바꾸지 않는다.** REQ-2026-131의 회귀 가드가 그 문구를 고정하고 있으므로, 마커만 추가하고
문장은 손대지 않는다. 마커 추가로 가드가 깨지는지 확인한다(needle이 절 경계에 걸치지 않아야 한다).

### DEC-3 — verb는 **기존 것을 쓴다**(`quickstart`)

새 verb를 만들지 않는다. 소비자 명령 표면을 늘리지 않는 것이 이 저장소의 방침이고,
이 verb가 하는 일("기존 파일의 관리 블록만 안전하게 동기화")이 그대로 확장되는 것이기 때문이다.

🔴 **이름과 실제 범위의 간극을 문서로 메운다.** 이제 이 verb는 Quick Start만이 아니라 **관리 계약 블록
전체**를 다룬다 — help·문서에 그렇게 적는다. 이름을 바꾸면 기존 문서·스크립트·소비자 습관이 깨지므로
바꾸지 않되, **이름이 범위를 다 말하지 못한다는 사실을 숨기지 않는다.**

🔴 **help·문서 갱신은 동작 변경과 _같은 phase_에 넣는다**(설계 r03 P1-c). 동작을 넓힌 phase가 단독으로
승인·커밋되면, 그 사이 사용자는 `--help`에서 "Quick Start 블록만"이라는 **거짓 안내**를 읽는다.
이 저장소가 반복해서 데인 "문서가 동작을 못 따라가는" 상태를 phase 경계로 스스로 만들지 않는다.

### DEC-4 — 안전 판정은 **문서 전체 마커 스트림**으로 한다(블록별 개수가 아니다)

🔴 설계 r01 P1: 블록마다 "여는 1 · 닫는 1"만 세면 **교차 중첩을 놓친다.**

```
<!-- commitgate:quickstart -->  …  <!-- commitgate:autonomy -->  …
<!-- /commitgate:quickstart --> …  <!-- /commitgate:autonomy -->
```

두 id 모두 "정상 쌍 1회"로 보이지만, 앞 블록을 치환하면 **다른 블록의 여는 마커가 지워진다.**
그래서 판정은 파일 안의 **모든 commitgate 관리 마커를 등장 순서대로 한 스트림**으로 훑는다.

```
스트림 규칙(스택 깊이 0/1만 허용):
  open(id)  : 스택이 비어 있어야 한다. 아니면 unsafe(중첩)
  close(id) : 스택 top 이 같은 id 여야 한다. 아니면 unsafe(교차 또는 짝 없음)
  끝        : 스택이 비어 있어야 한다. 아니면 unsafe(닫히지 않음)
  같은 id 쌍이 2회 이상 → unsafe(중복)
```

블록별 판정은 **스트림이 정상일 때만** 낸다.

| 상태 | 판정 | 행동 |
|---|---|---|
| 스트림 정상 · 쌍 있음 · shipped와 동일 | `noop` | 변경 없음 |
| 스트림 정상 · 쌍 있음 · 내용 다름 | `replace` | 블록만 치환(밖은 바이트 보존) |
| 스트림 정상 · 쌍 없음 | `insert` | 삽입 |
| **스트림 위반**(반쪽·중복·중첩·교차) | **`unsafe`** | 🔴 그 **파일의 모든 쓰기를 0건**으로 만들고 안내 |
| **`AGENTS.md`에 계약 마커 없음** | **`unmanaged`** | 🔴 쓰지 않되 **조용히 넘어가지도 않는다** — 아래 |

### DEC-4c — 계약 마커 없는 `AGENTS.md`는 **조용한 skip이 아니다**

🔴 설계 r02 P1: 현행 `quickstartBackfillTargets`는 계약 마커가 없는 `AGENTS.md`를 **목록에서 아예 빼서**
D21 입력에도 들어가지 않는다. 그러면 그 사용자는 `--apply` 후 "아무 일도 없었다"만 보고,
`req:doctor`도 OK를 낸다 — **요구사항의 "안내 + WARN"이 둘 다 성립하지 않는다.**

그래서 `unmanaged`를 **명시적 상태**로 모델링한다.

- 파일은 **건드리지 않는다**(자동 수정 금지 — 이 계약은 그대로).
- 계획 출력이 그 사실과 **손으로 할 일**을 말한다: 이 파일이 CommitGate 계약으로 인식되지 않는 이유
  (첫 줄 계약 마커 부재)와, 어느 파일에서 무엇을 가져와 붙여야 하는지.

🔴 **가리킬 경로는 `AGENTS.commitgate.md`다**(설계 r03 P1-b). 초안은 `AGENTS.template.md`를 가리켰는데,
그건 **패키지 내부 파일**이라 `npx commitgate`로 실행한 사용자의 저장소에는 없을 수 있다 — 열 수 없는
파일을 가리키면 "구체적 수동 병합 방법"이 되지 못한다. `init`은 계약 마커가 없을 때 대상 저장소에
**`AGENTS.commitgate.md`(계약 템플릿 사본)를 놓는다**(`KIT_AGENTS_CONTRACT_COPY_REL`) — 그것이 사용자가
실제로 열 수 있는 원본이다.

- 그 사본이 **있으면**: 그 파일의 관리 블록을 자기 `AGENTS.md`에 붙이라고 안내한다(블록 id를 함께 말한다).
- 그 사본이 **없으면**(예: 마커가 있던 시절에 설치된 뒤 마커를 지운 경우): 복구 경로를 안내한다 —
  `npx commitgate init`을 다시 실행하면 사본이 놓인다(기존 파일은 덮지 않는다).
- `req:doctor` **D21이 이 사유로 WARN**한다(부재·드리프트·식별 불가와 **구별되는 넷째 사유**).

⚠️ **`AGENTS.md`가 아예 없는 경우와 다르다.** 파일이 없으면 `init`의 몫이고 이 verb는 관여하지 않는다
(현행 계약 유지) — `unmanaged`는 "파일은 있는데 우리 계약이 아니다"이다.

🔴 **`unsafe`는 블록이 아니라 파일 단위로 전파된다.** 한 블록이라도 위반이면 그 파일에는 **아무것도
쓰지 않는다** — 정상인 다른 블록만 골라 쓰면, 손상된 마커 사이를 지나가는 치환이 사용자 문서를 삼킬 수 있다.

🔴 **`unsafe`를 `insert`로 흡수하지 않는다.** 반쪽 마커가 있는 파일에 또 삽입하면 다음 실행이
**어느 쪽을 관리 블록으로 볼지 모른다.** 안내는 무엇이 깨졌는지(어느 마커가 어디에 몇 개인지)와
손으로 무엇을 하면 되는지를 말한다.

### DEC-4a — 파일당 **한 번만 쓴다**(블록별 판정 → 파일별 최종 내용)

🔴 설계 r03 P1-a: 현행 계획 모델은 파일당 `action` 하나와 쓰기 하나를 전제한다. 파일×블록을 각각
**원본 기준으로** 계획하면, 두 블록이 모두 없는 `AGENTS.md`에서 두 `insert`가 각자 원본에 붙어
**마지막 쓰기만 남고 한 블록을 잃는다.**

계약을 명시한다.

```
파일 하나에 대해:
  content ← 원본
  for each 대상 블록(선언 순서):        // 🔴 앞 결과를 다음 입력으로 — 원본이 아니다
      { content, action } ← inject(content, block)
  actions ← 블록별 action 목록
  쓰기 ← actions 에 noop 아닌 것이 하나라도 있을 때 **한 번**
```

- **판정은 블록별**로 남긴다(계획 출력·doctor가 무엇이 왜 바뀌는지 말해야 하므로).
- **쓰기는 파일별 한 번**이다. 그래서 파일당 `action` 하나로 뭉치지 않고 `blocks: {id, action}[]`을 갖는다.
- 파일 전체가 `noop`이면 쓰지 않는다(멱등 계약 유지).

### DEC-4b — 새 블록의 **삽입 위치**를 명시한다

Quick Start는 "첫 H1 heading 뒤"에 삽입한다(REQ-2026-040). 자율 진행 계약은 `### 4-1`이라는 **문맥 의존
heading**이라 같은 규칙을 쓰면 계약 §4 앞에 놓여 계층이 뒤집힌다(설계 r01 observation).

- **부재 시 삽입 위치는 파일 끝**(append)으로 한다. 계약 본문의 자연스러운 자리(§4 뒤)를 문서 구조를
  추측해 찾으려 하면, 사용자가 절 순서를 바꿔 둔 파일에서 **엉뚱한 곳**에 들어간다.
- 🔴 삽입된 블록은 자기 heading(`### 4-1 …`)을 그대로 갖고 있으므로 **읽는 데 문제가 없다.**
  위치가 완벽하지 않은 것과 사용자 문서를 잘못 건드리는 것은 위험도가 다르다 — 안전한 쪽을 고른다.
- 이미 블록이 있으면(`replace`) **그 자리에서** 치환한다 — 위치를 옮기지 않는다.

### DEC-5 — doctor는 세 사건을 **구별해** WARN한다

D21의 입력을 블록 집합 기준으로 넓히고, 메시지에서 **네 사유**를 나눈다:
**부재(insert) / 드리프트(replace) / 식별 불가(unsafe) / 계약 아님(unmanaged)**.
이미 D21이 부재·드리프트를 나누고 있으므로(REQ-2026-101 DEC-2) 둘을 더한다.

🔴 **`unmanaged`가 D21 입력에 실제로 들어가야 한다.** 현행 대상 수집기는 그 파일을 목록에서 빼므로
(DEC-4c) 입력 구성부터 고쳐야 한다 — 메시지만 늘리면 그 사유는 **영원히 발화하지 않는다.**

🔴 **WARN 상한 유지.** `req:commit`이 doctor를 하드 게이트로 spawn하므로 FAIL이면 skew 난 소비자의
모든 커밋이 벽돌이 된다(D20·D21과 같은 근거).
🔴 **새 D-체크를 만들지 않는다.** 같은 사건(관리 블록이 설치본과 다르다)이므로 D21이 정확한 자리다 —
id를 늘리면 정본 표와 등록부만 커지고 사용자는 두 줄을 읽어야 한다.

### DEC-6 — 회귀는 **사용자 지침이 있는 실제 파일**로 검증한다

빈 파일이나 템플릿 사본으로는 이 REQ의 안전 축(바이트 보존)을 증명할 수 없다.
사용자 고유 절이 앞뒤에 있는 `AGENTS.md`를 만들어 적용하고 **세 가지**를 함께 본다:

1. 자율 진행 계약이 들어갔다.
2. **블록 밖 사용자 문장이 바이트 그대로다.**
3. 재실행이 멱등(변경 0)이다.

## Phase별 구현

- **phase-1**: `MANAGED_BLOCKS` + `blockRe(id)` + 블록별 판정(`unsafe` 포함) — 순수 코어 + 테스트.
- **phase-2**: 템플릿 마커 + verb/plan 배선(집합 순회) + 사용자 지침 보존 회귀(실 파일).
- **phase-3**: doctor D21 확장(식별 불가 구별) + 문서·`CHANGELOG.md`.

## 하위호환·안전

- Quick Start 블록의 기존 동작은 **불변**(같은 기계를 집합의 원소 하나로 돌린다).
- 기존 `AGENTS.md`는 **명시적 `--apply` 없이는 바뀌지 않는다**.
- 마커가 깨진 파일은 **아무것도 쓰지 않는다** — 이 REQ가 새로 막는 경로다.
- `init`(신규 생성)은 건드리지 않는다 — 템플릿에 마커가 생기므로 새 설치는 자동으로 블록을 갖는다.
