# REQ-2026-168 요구사항

## 무엇

`commitgate integrate` 가 **귀속 불가 커밋** 때문에 막혔을 때, 있지도 않은 delivery 묶음을 원인으로
지목한다. 진단을 사실대로 고치고, 비대화형에서 통과할 **감사 가능한 사람 결정 경로**를 만든다.

## 왜 — 소비자 리포트(meallo) + 재현

### 관측

`stopGate="auto"` · **delivery 묶음을 쓰지 않는**(디렉터리 자체가 없는) 저장소에서:

```
commitgate integrate — 차단:
  묶음(delivery) 레코드를 결속된 SHA 에서 읽지 못해 구성 티켓의 정책을 판정할 수 없습니다.
    해소: 묶음 레코드(`<ticketRoot>/delivery/<slug>.json`)가 통합 대상 SHA 의 트리에 있어야 합니다.
      레코드를 커밋한 뒤 다시 실행하세요.
```

없는 묶음의 레코드를 만들 수 없으므로 **실행 불가능한 안내**다. 비대화형에서는 통과 경로가 없다
(대화형 `y` 만 남는데, 그 자리는 fail-closed 판정을 사람이 덮는 자리다).

### 원인 (실측)

`policyTargetIds`(`bin/integrate.ts:679`)는 **구조적으로 다른 두 사유**로 `null` 을 낸다.

| 사유 | 조건 |
|---|---|
| ① 범위에 **귀속 불가 커밋** | `attested` · `unproven` · `invalid-evidence` · 분류에 없는 커밋 |
| ② delivery 레코드를 못 읽음 | `deliveryMembersOf(slug) === null` |

`resolveIntegrationPolicy`(`integrate.ts:701`)는 둘을 **한 메시지**로 뭉개고, 그 메시지는 ②만 설명한다.

리포트의 실행은 **①** 이었다. 증거는 리포트 본문에 있다 — `증거: … attested 1 …`.
`attested` 는 **의도적으로 귀속 불가**다(`range-attribution.ts:82` — *"리뷰 없이 예외 승인된 커밋을
자율 통합에 태우지 않는다"*).

리포트한 입력 그대로 재현했다. `deliveryMembersOf` 가 호출되면 예외를 던지도록 두었다:

```
policyTargetIds = null
kind = indeterminate
묶음(delivery) 레코드를 결속된 SHA 에서 읽지 못해 …     ← delivery 는 조회조차 되지 않았다
```

### 리포터의 추정 셋은 사실이 아니다 (정정)

- **"0.23.1 에서는 통과했다 → 런타임 버전이 원인"** — `v0.23.1` 에 **같은 코드가 그대로 있다**
  (`git show v0.23.1:bin/integrate.ts` → `unattributableCommits.length > 0` 분기 · `attested` 판정 불가).
  264·265 가 통과한 것은 그 범위에 attested 커밋이 **없었기** 때문이다. 바뀐 것은 버전이 아니라 입력이다.
- **"`req:next` 와 판정이 어긋난다"** — 다른 질문이다. `req:next` 는 *"이 feature 가 묶음에 속하는가"*,
  `integrate` 는 *"이 범위의 커밋이 어느 티켓 정책에 귀속되는가"* 를 묻는다. 어긋나 보인 것은
  **메시지가 엉뚱한 사유를 말했기 때문**이다.
- **제안 (a)(b)(c)** — 셋 다 게이트를 약화시킨다. (a) 는 이미 그렇고(묶음이 없으면 조회조차 안 한다),
  (b) 는 다른 질문을 합치는 것이며, (c) 는 예외 승인 커밋을 자율 통합에 태운다.

🔴 **게이트는 옳게 거부했다.** 옳게 거부한 게이트에는 탈출구가 아니라 **판정과 안내**를 고친다
(REQ-2026-161~163 이 세운 원칙).

### 판정 지점이 둘이다 (설계에서 함께 다뤄야 한다)

같은 사실을 보는 자리가 두 곳이고 **메시지 품질이 서로 다르다**.

| 자리 | 현행 메시지 |
|---|---|
| `resolveIntegrationPolicy` (정책) | 🔴 delivery 를 지목 — **틀렸다** |
| `scopeRangeProblem` (위임 권한, `delegation.ts:487`) | `병합 범위에 귀속을 판정할 수 없는 커밋 N건이 있다` — 정확하다 |

## 완료 기준

1. 귀속 불가로 막혔을 때 메시지가 **그 사실**을 말한다 — 해당 커밋의 SHA·범주를 나열하고, `delivery`
   라는 단어를 쓰지 않는다.
2. delivery 레코드 부재는 **실제로 그럴 때만** 그렇게 말한다.
3. `attested` 로 막혔을 때 안내가 실행 가능하다 — 왜 자율 통합 대상이 아닌지(의도된 설계)와, 사람이
   무엇을 하면 되는지를 말한다.
4. **비대화형 통과 경로**가 있다 — 사람이 **미리** 위임에 명시했을 때만. 기본은 불허이고, 원장에 남고,
   1회 소비된다(`--allow-push`·`--allow-bypass`·`--high-risk` 와 같은 패턴).
5. 🔴 그 경로가 `attested` **외의** 귀속 불가(`unproven`·`invalid-evidence`·분류 미상)를 열지 않는다.
6. 회귀 가드가 위를 고정한다(변이 검사로 실재 증명).
7. 변경한 소스를 import 하는 테스트 그린 · 통합 직전 전체 스위트 1회 그린.

## 비목표

- `attested` 의 귀속 규칙 변경(자율 통합 대상이 아니라는 판정 자체는 옳다).
- `req:next` 의 delivery 판정 변경(다른 질문이다).
- 대화형 최종 확인(y/N) 제거.
- strict 증거 검증 완화 — `unproven`·`invalid-evidence` 는 이 REQ 로 열리지 않는다.

## 별건 — 부기 트레일러 혼동 (같은 리포트)

리포터가 `CommitGate-Bookkeeping: true` 를 **손으로** 붙인 커밋이 `package.json` 을 바꿔 "손상 증거"로
막혔다. 게이트는 의도대로 동작했고 진단도 정확했다. 다만 **"부기 트레일러는 도구만 붙인다"** 는 서술이
계약 문서에 없어 같은 혼동이 재발할 수 있다 — 문서에 넣는다(`sync` 는 커밋하지 않으므로 고칠 코드는 없다).
