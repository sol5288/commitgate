# REQ-2026-138 요구사항

## 무엇을

랜딩 README **첫 소개**의 정지 서술을 REQ-2026-137이 세운 두 축 모델과 일치시킨다.

## 왜

REQ-2026-137이 "사람이 멈추는 지점" 절을 두 축으로 정정했지만, **그 절보다 200줄 앞에 있는 첫 소개**는
정지 축이 하나뿐이던 시절의 절대 표현을 그대로 담고 있다.

| 자리 | 현재 문장 | 왜 거짓인가 |
|---|---|---|
| `README.md:57` | 중간에는 멈추지 않고 **두 지점에서만** 확인한다 | 기본값 `reviewBudget.onSoftLimit: "ask"`에서 소프트 한도를 넘긴 재리뷰 회차마다 사람 예외가 필요하다 |
| `README.en.md:57` | 기본값에서 중간에 멈추지 않는다 | 같음 |
| `README.md:51` | 흐름도의 `human check` 칸이 사람은 **여기서만** 확인한다고 적는다 | 같은 배타 주장이다. 영문 흐름도(`this is where you step in`)에는 "만"이 없어 한글만 강하다 |

🔴 **바로 아래 줄과도 모순이다.** `README.md:59`/`README.en.md:59`는 이미 "6~8회는 사람이 예외를 기록해야
진행된다"고 적는다 — 57행을 읽고 59행을 읽으면 같은 화면 안에서 앞뒤가 맞지 않는다.

## 제약

- **장점은 지운다는 뜻이 아니다.** 기본값 `stopGate: "req"`에서 phase 커밋마다 사람을 부르지 않는 것은
  사실이고 이 도구를 쓰는 이유다. 지울 것은 그 사실이 아니라 **예외를 지우는 절대 표현**이다.
- 첫 소개는 요약 자리다. 정지 지점의 정본은 아래 "사람이 멈추는 지점" 절이므로, 조건을 길게 늘어놓지 말고
  **한 문장으로 밝히고 그 절로 연결**한다.
- 한국어·영어를 같은 의미로 갱신한다.
- 폐기 문구를 등재하면 **정정문에도 그 문자열을 남길 수 없다**(REQ-2026-104).
- 실재하지 않는 문장을 번역해 등재하지 않는다 — 영원히 발화하지 않는 항목이 는다(`retired-claims.ts` 등재 규칙).

## 완료 기준

- `README.md:51`·`:57`, `README.en.md:57`이 두 축 모델과 일치한다.
- 옛 문구가 `RETIRED_CLAIMS`에 등재되고 `docs-stale-claims`가 그린이며, 재삽입 시 red임을 확인했다.
- `npm run docs:lint` · `docs-stale-claims` · `readme-landing` 통과.
