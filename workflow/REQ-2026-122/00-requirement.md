# REQ-2026-122 요구사항

테스트 계층 실행 스크립트 — 실측 병목 12파일을 통합 계층으로 분리

## 배경 (무엇이 문제인가)

전체 스위트가 63파일·2,678테스트로 자랐고, 2026-08-10 실측(로컬 win32·maxWorkers 2)에서 테스트
시간 합 1,450초 중 **상위 12파일이 91.2%**를 차지한다(상위 4 — `init` 451s · `uninstall` 234s ·
`req-review-codex` 196s · `delivery-verbs` 151s — 만 71%). 전부 임시 저장소를 만들고 git/프로세스를
스폰하는 **통합 성격** 테스트다. REQ-2026-100이 실행 계층 규칙("phase 중엔 변경 import 테스트만,
전량은 통합 직전 1회")을 문서화했지만, **"빠른 부분집합"을 실행할 명령 자체가 없다** — 계층은
말로만 있고 실행 수단이 없다. timeout을 늘리는 식의 대응은 하지 않는다(병목 식별·분리가 요구).

## 요구

- **R1 · 계층 정의의 SSOT** — 통합 계층 파일 목록을 코드 한 곳(`tests/tiers.ts` 류)에 실측 근거와
  함께 둔다. 이번 측정의 상위 12파일이 초기 목록이다.
- **R2 · 실행 수단** — `npm run test:fast`(통합 계층 제외 = 순수·빠른 부분집합)와
  `npm run test:integration`(통합 계층만)을 제공한다. **`npm test`는 무변경**(전체 — 권위 판정,
  CI·통합 직전 용도 그대로).
- **R3 · 완전성 가드** — 계층 목록의 파일이 실제로 존재하고(오탈자·이동으로 조용히 빠지는 것 방지),
  fast ∪ integration = 전체 스위트임을 테스트로 고정한다(어느 파일도 두 계층 사이에서 유실되지 않음).
- **R4 · 문서** — `docs/development.md`(한/영)에 계층·명령·실측 근거를 기록한다. 게이트는 여전히
  테스트를 실행하지 않는다(REQ-2026-100 계약 유지 — 이것은 비용 도구다).

## 제약

- `npm test`의 의미·범위·설정(maxWorkers 등) 무변경 — 전량 검증의 권위는 그대로다.
- 소비자 계약(AGENTS.template 등) 무변경 — 이 스크립트는 이 저장소의 개발 도구다.
- 테스트 파일 이동·개명 없음(이력·역의존 grep 보존) — 분리는 목록 기반이다.

## 완료 기준

1. `test:fast`가 통합 계층 12파일을 제외한 나머지만 실행한다(파일 수 단언 가능).
2. `test:integration`이 그 12파일만 실행한다.
3. `npm test`는 이전과 동일하게 전체를 실행한다(워크스페이스 도입이 기본 실행을 바꾸지 않음).
4. 목록에 실재하지 않는 파일이 있으면 가드 테스트가 실패한다(변이: 목록에 가짜 경로 추가 → red).
5. fast ∪ integration = `tests/**/*.test.ts` 전체(집합 동일성 테스트).
