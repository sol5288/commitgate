# REQ-2026-080 요구사항 — Node 18 지원 중단 (최소 Node 20)

## 사용자 결정 (2026-07-28)

> "B Node 18을 제외하자. Node 20 부터 지원되는걸로 매뉴얼도 싹다 개선하자
>  Node 18 너무 오래되서 요즘 거의 안쓰지 않나?"

선택: **최소 Node 20 · CI 매트릭스 `[20, 22, 24]`**.

## 근거

### ① 교착이 node 18에서만 난다 (REQ-2026-077·079 실측)

`macos-latest · node 18`에서만 `npm test`가 교착한다. 같은 커밋의 node 20·22는 매번 통과했다.
REQ-2026-079가 `pool: 'threads'`로 고쳐 보려 했으나 **실패**했다
(`workflow/REQ-2026-079/03-verification.md`) — 원인 조건 자체를 없애는 것이 남은 길이다.

### ② Node 18은 EOL 15개월 (공식 일정 실측)

| 버전 | EOL | 상태(2026-07-28) |
|---|---|---|
| Node 18 | 2025-04-30 | EOL |
| **Node 20** | 2026-04-30 | EOL이지만 보급률을 고려해 **최소로 채택** |
| Node 22 | 2027-04-30 | 지원 중 |
| Node 24 | 2028-04-30 | 지원 중 |

출처: `nodejs/Release` 저장소의 `schedule.json`.

## 수용 기준

1. `package.json`의 `engines.node`가 **`>=20`**이다.
2. CI 매트릭스가 **`[20, 22, 24]`**다. 🔴 잡 수는 9개(3 OS × 3 node)로 현행과 같다.
3. 🔴 **문서에 Node 18 요구가 남지 않는다.** README·quick-start·development·RELEASING 한/영 전부.
4. 🔴 **`docs/ssot-design/`의 "현재 사실" 문서도 갱신한다**(01·02·10·README) —
   그 디렉터리는 "현재 구현의 사실"을 자처하므로 남겨 두면 **거짓 사실**이 된다.
   REQ-2026-073·078에서 반복한 실수(본문만 고치고 그림·표는 남김)를 되풀이하지 않는다.
5. 🔴 **날짜가 붙은 검수 이력은 고치지 않는다**(`11-test-strategy…`·`13-review-and-validation-log`).
   그것은 **그때 실제로 그랬다는 기록**이다 — 고치면 역사를 위조하는 것이다.
6. CHANGELOG에 **호환성 깨짐(breaking)**임을 명시한다.
7. `npm test` green · `docs:lint` green · CI green.

## 🔴 사용자 조치가 필요한 항목

매트릭스가 바뀌면 **잡 이름이 바뀐다**(`… node 18` 사라지고 `… node 24` 생김).
저장소 **branch protection의 required status checks 목록**을 갱신하지 않으면
PR 경로에서 **존재하지 않는 체크를 영원히 기다린다.**
direct push(B1) 경로는 막히지 않지만, 설정은 고쳐 두어야 한다.
