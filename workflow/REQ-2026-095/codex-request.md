# REQ-2026-095 phase-1 리뷰 요청 — 안내·별칭·경고

## 배경

소비자 버그 리포트(Windows/pnpm): `req:commit -m`에 여러 줄 메시지를 넘기면 본문이 사라지고 줄바꿈이
리터럴 `\n`으로 바뀐다. 소비 저장소 커밋 6건이 그 상태로 병합됐다.

직접 재현한 결과 **pnpm 문제가 아니라 Windows `.cmd` shim 문제**였고, **npm이 더 나쁘다**(개행 이후를
조용히 버린다 — 탐지 불가). `npx`·`pnpm exec <bin>`·`npx tsx`도 같다. `--message-file`만 온전하다.
그 기능은 **이미 있고**(REQ-2026-018) 문제는 **정본 안내가 그것을 가리키지 않는 것**이었다.
설계는 r03 승인 상태다.

보여야 하고, 그래야 **배선 자체를 관측**할 수 있다.

**문서 4종** — troubleshooting(한/영)에 증상·실측표·해법, workflow(한/영)의 기존 한 줄 안내를
**이유와 함께** 강화(기존 문장은 이유가 없어 건너뛰기 쉬웠다).

## r01 P1 대응 (이 라운드)

**지적**: workflow 문서 한/영 두 곳에서 pnpm 변환 결과를 설명해야 할 리터럴 백슬래시-n이
**실제 줄바꿈을 사이에 둔 빈 코드 span**으로 기록됐다. 사용자가 pnpm이 무엇으로 바꾸는지 알 수 없어
R4(증상·해법 문서화)와 충돌한다.

**수정**: 두 곳을 한 줄 인라인 코드로 고쳤다(한: "리터럴 `\n` 두 글자로 바꿉니다",
영: "literal two-character `\n`"). **전수 확인**도 했다 — troubleshooting 한/영·CHANGELOG의
같은 표기는 전부 정상이었고, 깨진 형태(백틱으로 끝나는 줄)는 이제 0건이다.

⭐ 원인은 문서를 셸 스크립트로 쓰면서 백슬래시-n이 **실제 개행으로 확장**된 것이다. 이 세션에서 같은
이스케이프 사고를 여러 번 냈고(이 요청서 자체도 한 번 당했다), 매번 문서 본문을 망가뜨렸다.
→ 백슬래시가 들어가는 문서는 셸을 거치지 않는 편집 도구로 쓰고, **쓴 뒤 렌더 결과를 확인**한다.

## 리뷰 포인트

**P1. 경고 위치가 옳은가.** `assertSetupComplete` **직후**, doctor·게이트보다 앞이다. 근거는 둘
(자문 성격 + 배선 관측 가능성). 그런데 이 위치는 **티켓이 존재하지 않아도** 경고가 나온다는 뜻이다.
오타로 잘못된 REQ id를 준 경우에도 경고가 뜨는데, 그것이 혼란스러운가?

**P2. 안내를 `diagnostics`에 넣은 것.** `renderAction`이 이미 `  - <줄>`로 렌더링해 렌더러 변경이 없다.
다만 `diagnostics`는 원래 진단용이라 "안내"가 섞인다. 별도 필드가 나은가, 아니면 사용자에게 보이는
결과가 같으니 무방한가?

**P3. 판정의 경계.** `looksLikeCollapsedMessage`는 "리터럴 `\n` 있음 **AND** 실제 개행 없음"이다.
`'subject\nbody with literal \\n inside'`(둘 다 있음)는 **false**로 뒀다 — 전달은 성공했으므로.
이 경계가 맞는가? 붕괴 후 사용자가 개행을 하나 덧붙인 경우를 놓치는데, 그건 감수할 만한가?

**P4. 문구가 정직한가.** 경고가 "npm·npx는 조용히 버려 흔적이 남지 않으니 이 경고가 없어도 안전하다는
뜻은 아니다"라고 말한다. 이것이 사용자에게 유용한 정보인가, 아니면 불안만 주는가?

**P5. `-F` 별칭의 위험.** `-F`는 단일 문자 플래그다. 기존 인자와 충돌하거나, 값이 `-`로 시작할 때
문제가 되는가? (값 부재만 거부하고 접두 검사는 하지 않는다 — `--message-file`과 동일 취급.)

**P6. RUN 명령을 그대로 둔 판단**(DEC-1). 가장 안전한 것은 RUN이 항상 `--message-file`을 쓰는 것이지만
그러면 에이전트가 파일을 먼저 써야 해 "출력된 명령을 그대로 실행" 계약이 깨진다. 자리표시자에 `(한 줄)`을
넣고 안내를 옆에 붙이는 절충이 충분한가?

**P7. 우리가 고치지 못하는 것.** npm의 조용한 절단은 남는다. 문서·경고가 그 한계를 말하는 것으로
충분한가, 아니면 더 강한 조치(예: `req:commit`이 패키지매니저 경유 실행을 감지해 항상 안내)가 필요한가?
