# REQ-2026-081 설계 — 소비자가 부딪히는 지점에 안내를 둔다

> 정본 결정은 SSOT(해당 DEC). 본 문서는 그 결정을 문서 구조에 어떻게 반영할지 기록.

## 현재 상태(변경 대상)

`docs/upgrade.md`는 **버전과 무관한 일반 안내**만 담는다:

```
# 업그레이드 (0.x)
  ① 캐럿 범위가 0.x minor를 막는다
  ② vendored 자산은 런타임과 별개로 갱신된다(`sync`)
## 예전 설치본에서 옮겨오기 (`migrate`)
```

→ **버전별 절이 없다.** 0.12.0이 이 프로젝트의 **첫 호환성 깨짐**인데 놓을 자리가 없다.

## 핵심 설계 결정

### DEC-1 — 🔴 `upgrade`에 **버전별 절**을 만든다

`## 버전별 주의사항` 아래 `### 0.11 → 0.12 — Node 20 이상이 필요합니다`를 둔다.

왜 일반 안내에 한 줄 끼워 넣지 않는가: 앞으로도 breaking change가 나올 텐데,
그때마다 본문에 섞으면 **어느 버전 이야기인지 알 수 없어진다.**
버전별 절은 **읽는 사람이 자기 버전만 보고 넘어갈 수 있게** 한다.

🔴 이 절은 **누적**된다 — 지우지 않는다. 0.10에서 올라오는 사람도 0.11·0.12를 모두 지나야 한다.

### DEC-2 — 🔴 **실제 출력**을 적는다

"Node 20이 필요합니다"만 적으면, 사용자는 자기가 본 오류가 그것인지 모른다.
실측한 그대로 옮긴다:

```
npm warn EBADENGINE Unsupported engine {
npm warn EBADENGINE   package: 'commitgate@0.12.0',
npm warn EBADENGINE   required: { node: '>=20' },
npm warn EBADENGINE   current: { node: 'v18.20.4', npm: '10.7.0' }
```

그리고 **두 가지 경로가 다르다**는 것을 말한다(실측):
- 기본 설치 → **경고만**, 설치는 된다(하지만 동작을 보장하지 않는다)
- `--engine-strict` → **exit 1 · 설치 안 됨**

### DEC-3 — 🔴 **"고쳤다"가 아니라 "지원하지 않는다"** (REQ-080 DEC-2 승계)

문서는 Node 18 교착을 **해결했다고 말하지 않는다.** 근원 원인은 미해결이고,
Node 18로 되돌리면 교착도 돌아온다. 사용자가 "그럼 18에서 그냥 쓰면 되나?" 물었을 때
**"경고를 무시하고 쓰면 CI가 간헐적으로 멈출 수 있다"**는 사실이 전달돼야 한다.

### DEC-4 — 지원 범위 표에 **런타임 행**을 맨 위에 둔다 — 내용까지 계약한다

`guarantees`의 표는 패키지 매니저부터 시작한다. 🔴 **런타임이 더 앞선 축**이다 —
Node 버전이 안 맞으면 패키지 매니저 이야기는 의미가 없다.

🔴 **행의 내용을 계약으로 못박는다**(설계 r01 P1). "Node 20+" 같은 약한 표현은 **불충분하다** —
어느 버전이 **실제로 검증됐는지**가 이 문서의 값어치이기 때문이다.

| 반드시 담을 것 | 근거 |
|---|---|
| **Node 20 · 22 · 24 에서 매 릴리스 CI 검증** | 매트릭스가 3 OS × 이 세 버전이다 |
| 🔴 **Node 18 미지원** | `engines: >=20` — 설치가 경고되거나(기본) 실패한다(`--engine-strict`) |
| 🔴 **20 은 EOL(2026-04-30)이지만 지원한다** | 보급률을 이유로 남긴 의도적 선택이다. 적지 않으면 "왜 EOL을 지원하나"가 실수로 보인다 |

### DEC-4b — 🔴 G1은 Node 18 사용자에게 **선택지를 준다** (설계 r01 P1)

"Node 20이 필요합니다"로 끝내면 18 사용자는 막힌 채 남는다. **세 갈래를 모두 적는다**:

| 선택지 | 결과 | 권장 |
|---|---|---|
| **Node 20 이상으로 올린다** | 정상 동작 | ✅ **권장** |
| **`commitgate@^0.11`에 머문다** | 0.12 기능은 못 받는다. 🔴 그리고 **macOS + Node 18 조합에서 테스트 스위트가 간헐 교착**하는 문제가 그대로다(0.11도 고치지 못했다) | 임시책 |
| Node 18에서 0.12를 강행(경고 무시) | 🔴 **지원하지 않는다.** 위 교착이 그대로이고 검증도 하지 않는다 | ❌ |

🔴 두 번째 선택지에 **교착이 남는다**는 사실을 반드시 적는다 — 0.11로 내려가면 해결된다고
오해하면 안 된다. 그 문제는 **어느 버전에서도 고쳐지지 않았고**, 0.12는 조건을 없앴을 뿐이다.

### DEC-5 — troubleshooting은 **증상 → 원인 → 조치** 형식을 따른다

기존 12개 항목이 모두 **증상 문장**으로 시작한다(`**…가 막힙니다.**`).
같은 형식을 지킨다 — 사용자는 자기 증상으로 찾는다.

### DEC-6 — G4(development)는 **기여자용**이라 짧게

`testTimeout` 30초와 `hang-probe.yml`은 소비자와 무관하다.
🔴 다만 **왜 그 값인지**는 적는다 — 값만 적으면 다음 사람이 근거 없이 바꾼다.

## 하위호환·안전

- 문서 전용 — 코드·게이트·보장 계약 불변.
- 🔴 `guarantees`의 **안전 문구는 건드리지 않는다**(랜딩 4문구와 별개지만 같은 성격).
  런타임 **행 추가**이지 기존 진술 수정이 아니다.
- 링크는 `docs:lint`가 검증한다. 한글 앵커는 절대 blob URL에서 해석되지 않는다(REQ-073 실측).
