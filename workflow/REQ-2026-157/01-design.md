# REQ-2026-157 설계

## DEC-1 — 사실을 한 곳에서 말하고 나머지는 링크한다

`setup` 이 묻는 4개와 그 의미의 **정본은 `docs/quick-start.md` 의 "setup이 묻는 것"** 절이다.
나머지 문서(README·guarantees·agent-prompt)는 **한 줄 요약 + 링크**만 둔다.

🔴 **같은 표를 네 곳에 복제하지 않는다.** 이 저장소는 "새 절 추가 ≠ 갱신"으로 세 번 실패했고
(REQ-073·104·153), 복제된 서술은 다음 변경에서 반드시 갈라진다. 지금 고칠 5곳 중 3곳이
**같은 사실을 각자 적어 둔 탓에** 틀린 것이다.

## DEC-2 — 두 축을 **분리해서** 설명한다 (초보자 기준)

지금 문서가 헷갈리게 만드는 지점은 하나다: **`stopGate` 와 `onSoftLimit` 이 다른 축**인데
"멈춤"이라는 같은 말을 쓴다.

| | 무엇을 정하나 | 성격 |
|---|---|---|
| `stopGate` | **사람이 승인할 지점** — 커밋·통합 | 🔴 **안전** 축 |
| `reviewBudget.onSoftLimit` | 재리뷰가 **예산을 넘겼을 때** 계속할지 | 💳 **비용** 축 |

문서에 이 표를 넣는다. 그리고 `onSoftLimit: "auto"` 옆에는 **무엇이 그대로이고 무엇이 없어지는지**를
둘 다 적는다.

🔴 **"사람 확인은 그대로"라고 쓰면 안 된다**(설계 r01 P1). `auto` 는 **예산 초과 뒤 요구되던 사람
예외 승인을 실제로 없앤다**. 안심시키는 문장을 쓰면 사용자가 **잃는 확인 하나를 모르고** 고른다.
두 확인을 구분해 적는다:

> `auto` 를 골라도 **`stopGate` 가 정한 사람 확인(커밋·통합 승인)은 그대로**입니다.
> 다만 **예산을 넘긴 뒤 요구되던 "사람 예외 승인"은 없어집니다** — 그만큼 사람이 개입하지 않고
> 돈을 더 쓰게 됩니다. 어느 값이든 `hardCap`(기본 8) 을 넘기면 차단됩니다.

### 🔴 "N회차"로 쓰지 않는다 — 두 한도의 계수 기준이 다르다 (설계 r02 P1)

실측(`checkReviewBudget`):

```
attempt = dispatched + 1
if (dispatched >= hardCap)      → hard-blocked   ← **호출 횟수**(dispatched)
if (productive < autoBudget)    → allow          ← **판정이 나온 횟수**(productive)
onSoftLimit === 'auto' ? soft-auto : needs-exception
```

- `autoBudget`(소프트)는 **판정이 나온 회차만** 센다. 응답이 무효(invalid)면 `void_attempts` 로
  빠져 productive 에 들어가지 않는다.
- `hardCap`(절대)은 **실제로 나간 호출**을 센다 — 무효 응답도 돈이 나갔으므로 빠지지 않는다.
- 🔴 그래서 **"6회차부터 예외가 필요하다"는 틀리다.** 1~5회 중 한 번이 무효였다면 6번째 호출은
  여전히 자동으로 통과한다(productive=4).

문서는 **횟수 번호 대신 조건**으로 쓴다:

> 판정이 나온 리뷰가 `autoBudget`(기본 5)회를 채우기 전까지는 자동입니다.
> 채운 뒤에는 `onSoftLimit` 이 정합니다 — `ask`(기본)면 회차마다 사람 예외 승인이 필요하고,
> `auto` 면 승인 없이 진행합니다.
> **무효 응답은 판정 횟수에 들어가지 않지만 호출 횟수에는 들어갑니다** — 그래서 `hardCap`(기본 8)
> **호출**을 채우면 어느 값에서도 차단됩니다.

🔴 초보자가 `auto` 를 "안전장치를 끄는 옵션"으로 읽지 않게 하되, **없어지는 것을 감추지도 않는다.**
`setup` 프롬프트의 "(비용 통제 — 안전 게이트가 아닙니다)"는 축을 구분하는 말이지 "아무것도
없어지지 않는다"는 뜻이 아니다.

## DEC-3 — 설정 종속 서술은 **조건문**으로 쓴다

"6~8회는 사람 예외가 필요하다"처럼 단정하지 않는다. 형식을 고정한다:

```
기본값(`ask`)에서는 … / `auto` 로 바꾸면 … / 어느 값이든 `hardCap`(기본 8) 을 넘기면 차단됩니다.
```

- 🔴 **세 번째 절은 항상 붙인다** — `hardCap` 은 두 값 **모두에서** 차단하는 백스톱이고,
  그것이 "무한 재리뷰 루프를 막는다"는 보장의 근거다. 앞 두 절만 쓰면 `auto` 가 무제한처럼 읽힌다.
- `docs/guarantees.md` 는 **보장 문서**다. 설정에 따라 달라지는 것을 절대 규칙처럼 적으면
  그 문서 전체의 신뢰가 떨어진다.

## DEC-4 — 한/영을 **같은 커밋에서** 고친다

이 저장소는 문서를 이중언어로 유지한다. 한쪽만 고치면 다른 쪽이 **틀린 채로 남고**, 그것을
발견하는 것은 다음 외부 검토다(이번이 그 예다).

- 🔴 **번역이 아니라 같은 사실을 쓴다.** 영문판이 한글판의 문장 구조를 따라갈 필요는 없지만,
  **숫자·기본값·선택지 목록은 바이트로 같아야** 한다.
- 회귀 가드: 두 판이 같은 **질문 개수**와 같은 **선택지 집합**을 말하는지 테스트로 고정한다.

## DEC-5 — 회귀 가드는 **소스를 정본으로** 삼는다

문서가 다시 갈라지지 않게 하려면, 문서를 사람이 아니라 **코드와 대조**해야 한다.

```
setup 이 실제로 묻는 키 개수 = buildQuestions(...).length
  ↔ quick-start(한/영)의 setup 질문 표 행 수
각 질문 행을 **키로 식별**하고(행에 설정 키가 코드로 적혀 있다):
  stopGate 행                     ↔ CONFIG_SCHEMA 의 stopGate enum + 기본값
  reviewBudget.onSoftLimit 행     ↔ 같은 스키마의 enum + 기본값(`ask`)
```

🔴 **행 수와 `stopGate` 만 대조하면 부족하다**(설계 r01 P1). 네 번째 행에서 `auto` 를 지우고
`ask` 만 남겨도 행 수는 4이고 `stopGate` 행은 그대로라 **가드가 전부 통과한다** — 그런데 실제
setup 은 여전히 둘을 제시하므로 사용자가 틀린 선택지를 본다. **선택지를 대조하는 모든 행을
키로 결속**한다.

- 🔴 **문서에서 문서를 검사하지 않는다** — 그러면 둘 다 틀린 채로 통과한다.
- 🔴 **정규식으로 산문을 파싱하지 않는다.** 표의 행만 센다(마크다운 표는 구조가 고정적이다).
  산문까지 파싱하려 들면 그 파서 자체가 다음 결함이 된다(REQ-2026-041 에서 겪었다 —
  손수 검증 oracle 은 바닥이 없다).
- 🔴 **틀린 것을 못 잡는 가드는 넣지 않는다.** 변이 검사로 확인한다: 표에서 행 하나를 지우면 red,
  `auto` 를 목록에서 빼면 red.
